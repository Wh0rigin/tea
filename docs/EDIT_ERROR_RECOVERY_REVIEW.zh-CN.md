# 编辑错误恢复：结果与过程分析

## 测试对象与结论

本阶段只改错误分类与恢复建议，尚未实现同轮规则提示去重、编辑前规则检查或测试前提提示。候选 55c0975，基线 df89c92，两边均保留上一版目录规则发现。

GLM-5.3-flash、enabled / low、流式，3 道自编题各组各重复 2 次，12 次全部完成、用量全部已知，无付费重试。代码行为、目录约定、文件保持与完整验收均为 6/6 → 6/6。相关测试 16/16，完整回归 362/362，零跳过。

全尝试 provider Tokens：128,179 → 121,349，减少 5.33%；请求 41 → 39，减少 4.88%。缓存读写按既有规范化口径计入，思考不重复加算。控制费用估算 0.235868 USD，非账单。上一轮未知样本及其 1 USD 预留仍保留，不混入本轮百分比。

数值通过预先冻结的筛选门槛；但机制归因不足、重复间波动较大，不能称为已证实的稳定优化。2026-10-18 用户确认保留该修改，纳入正常 CLI 的编辑错误处理，无需新增开关；结构化建议沿用既有 capabilityFeedback 设置。尚未合并 PR，不自动推进下一项实验。

## 分题与波动

- 普通新建题：25,379 → 24,220，减少 4.57%；两边都没有触发新的错误反馈，不能把下降归因于本改动。
- 目录重试题：47,216 → 39,492，减少 16.36%；候选两次均没有触发新反馈，基线一次用错新建工具。候选首次避免工具误用发生在反馈之前，不能归因为尚未看到的新反馈。
- 分页题：55,584 → 57,637，增加 3.69%；这是两边均实际经历已有文件错误的任务组，没有得到 Token 下降。
- 第一轮：66,332 → 73,730，增加 11.15%；第二轮：61,847 → 47,619，减少 23.01%。两轮方向相反，小样本波动明显。

## 新反馈有没有被使用

两组各出现 3 次已有文件新建错误，均最终补丁恢复。基线错误分布在一次重试题和两次分页题；候选全部在分页题，首轮同一路径错误两次，第二轮一次。因此这不是严格配对的错误恢复消融。

错误后至补丁成功前，基线目标文件重读 1 次，候选 0 次；两边列目录均为 0 次。它支持“新反馈允许模型直接复用证据”这一可行路径，但只是很少的观测，不能解释全部 6,830 Tokens 的差额。

模拟 Agent 的专项回归同样验证了读源码 → FILE_EXISTS → 不重读直接补丁 → 实际 Node 测试通过；其模拟调用不作为真实 Token 收益。

## 暴露的问题

### 1. 明确反馈仍未阻止下一轮重复用错工具

候选首轮分页在第 3 个模型轮次调用 write_file 被拒绝，第 4 轮再次对同一已有文件调用 write_file，第 5 轮才 apply_patch。独立审计保留了模型轮次编号，确认不是同一轮预先生成的多个操作。

因此反馈改得更清楚不等于模型立即遵守，单改文案未解决工具语义与模型习惯的冲突。它省去了一次重读，却增加了一次错误重试。本阶段没有自动改写成覆盖写入，也没有放宽权限或精确补丁检查。

### 2. 测试前提错误继续产生额外轮次

候选首轮分页的新回归测试在默认页大小为 2 时断言返回全部 4 条数据，失败后显式传入 limit:50，重新验证通过。既有公开测试与隐藏行为测试均通过，未改已有测试掩盖错误。

本轮工具错误总数 3 → 4，其中候选为 3 次已有文件错误加 1 次验证失败。Token 总数下降没有意味着错误次数下降。

### 3. PATCH_NOT_FOUND 与 PATCH_AMBIGUOUS 只有离线覆盖

本轮真实模型没有触发这两种分类；专项测试验证它们保持拒绝并给出不同恢复建议。不能声称这部分改动已经带来真实模型收益。

## 下一步建议

优先评估“同轮规则提示合并”，与当前候选分开对照。工具误用若继续处理，应评估创建工具命名、模型看到的工具契约和重复错误反馈是否一致；先不要再增长通用系统提示，也不自动将拒绝操作转成覆盖写入。

如果要确认本阶段的因果收益，应另行冻结独立的恢复微基准：让两边从相同已读取源码、相同失败调用后的状态继续，比较反馈后的恢复。必须标为受控恢复任务，不混同完整编码任务或自动补跑本轮。
