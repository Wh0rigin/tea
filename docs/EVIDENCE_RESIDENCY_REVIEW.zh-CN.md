# 第二阶段：ContextOS 驻留证据校验

## 目标与范围

修复读取证据的失效范围，生产变更仅涉及 `src/context-assembler.mjs`。本阶段没有加入任务规划、停滞提醒或需求覆盖判定，也没有改变模型提示词、工具定义、ContextOS 目标、摘要与 GC 策略。

候选源码：`778a54ff1773e51d4f1ca1211fda4249a1eb848c`；基线：已完成命令与产物生命周期修复的 `f03052a5b41453c206f9375bd5c004842cab0dc4`。

## 复现的两类问题

1. **失效范围过宽。** 原实现处理某条旧证据的逐出或失效时，按文件清空 `readEvidence` 与 `presentedSource`。因此，同文件旧版本已过期、当前版本仍完整驻留时，当前版本的缓存仍会被删掉；后续读取会重新输出全文。
2. **实际请求缺少全文时，缓存可能仍存在。** 若当前请求不再包含某段源码，而完整历史中仍有该段或只剩“Evidence unchanged”回执，单靠逐出事件清理不能证明模型仍能看到原文。读取去重可能错误声称原文仍在历史中。

这两类问题通过自编确定性测试复现，不依赖 DeepSWE 隐藏测试。相同的 13 项测试运行在独立导出的基线源码上为 **6 通过、7 失败**，候选为 **13/13 通过**。这是机制回归结果，不是模型解题率。

## 修改方式

- 在最终请求投影与无收益回退完成后，从实际发送的工具结果收集完整、版本有效的 `read_file` 源码范围。
- 同时检查规范路径、完整 SHA-256、行范围及完整行内容；已过期源码、短回执和截断输出不作为完整证据。
- 只保留仍受上述驻留源码支撑的读取缓存；同文件其他版本或其他范围分别处理。
- `presentedSource` 只保留实际可见且完全一致的行。
- 仅裁剪已有缓存，不重建压缩或 GC 已经清空的缓存。`commit:false` 的尺寸预览不修改两份缓存。
- 不把召回预览、部分召回页或摘要推断为完整读取；无法证明完整驻留时，下一次 `read_file` 正常返回当前源码。

无需新增模型请求、持久化格式或每轮提示。代价是每次实际组装请求时多一次驻留读取范围检查；遇到无法确认完整性的输出，会保守地重新提供源码。

## 离线验证

- 专项涵盖：Agent/用户修改、同路径新旧版本、分离行范围、缺少全文的回执、实际请求缺段、真正逐出后的重读、无收益回退、Unicode/BOM/CRLF、截断、只读预览及普通 Agent 编辑验证循环。
- Windows 最终完整回归：**393 通过、0 失败、1 跳过 / 394**；跳过项为本机缺少 Go 的真实测试。首次全套中另有一次本地网关 502，原日志保留；单独重跑与之后两次完整回归通过，没有为此修改生产网关或放宽断言。
- Linux 原始任务镜像、Node 24、无网络：**394/394 通过，无跳过**。
- 原有 runtime-smoke：**12/12 独立验收通过**；controlled replay 完成。均无 provider 调用。
- 双版本实际 Pier 适配器预检：每组 **10 条固定 SSE 响应、9 次真实工具操作**，两组补丁 SHA-256 一致，分别在独立容器应用并通过测试。自编夹具中重复读取由全文变为短回执。
- 该夹具读取输出 **19,464 → 13,309 字节**；累计序列化请求 **156,099 → 143,386 字节**。只能说明同一脚本轨迹下的字节变化，**不是 provider Token 收益、DeepSWE 解题结果或生产收益预测**。

## 真实对照

付费前冻结并提交了 [协议](../benchmarks/reports/evidence-residency-deepswe-20261019/protocol.json)。两道原 DeepSWE 任务各运行基线、候选一次，共四次；两组共用修正后的命令权限和产物导出入口。

GLM-5.3-flash、enabled/low、流式、输出 4,096；总窗口 216,000、ContextOS 32,000 字节；每题 96 工具、128 转发、30 分钟、5 USD 控制预算，整轮 20 USD。出现未知用量或基础设施异常时停止，保留记录，不自动重试。

两题已看过历史验收反馈，仅作已见回归；单次配对不能证明泛化或稳定的因果收益。完整任务验收优先，失败样本的较低用量不算节省；双方完整通过的配对另行报告。

### 真实执行结果：对照未完成，不能判断 Token 收益

首组基线 Helm 提交 20 次请求，其中 **19 次完整、1 次部分用量**。第 20 次响应缺少 SSE `message_stop`；运行时错误为模型阶段的 `RUNTIME_ERROR`。转发侧同时记录 BrokenPipe，但这不能单独确定是服务端、网络还是客户端超时引起的中断。

按冻结协议停止整轮，**没有重试**。保留 **5 USD 整题预留**，不是声称已花费 5 USD。已报告的 Token 下界为 **398,005**，完整总量未知，不能记为零。基线与转发均记录 20 次请求，次数相符不代表最后一次计费用量完整。

基线在中断前执行 36 次工具调用，无成功编辑；官方独立验收新增报告项 **0/5**、既有行为 **2/2**，整题未通过。候选 Helm 与两组 mnamer 均**未启动**，不能算作候选失败或零 Token 样本。没有完整配对，所以真实 Token 提升/下降百分比与正确率变化均**不可计算**。

基线轨迹中，21 次完整源码输出包含 10 次相同范围、相同源码版本的重复输出；另有截断读取。它们发生在编辑前，说明真正逐出后的重读与任务推进仍是独立问题。本次修复不会禁止必要重读，也未加入推进控制。

另外，Pier 收集阶段将产物目录的 `manifest.json` 改写为框架自己的清单。分析脚本因此首次读取失败；改为读取原先保存在 `agent/commit.json` 的 finalizer 标准输出，核对其补丁 SHA-256 与现存 `model.patch` 一致后提取元数据。没有修改候选源码或解法、重跑模型或重新判分。后续适配器应避免使用框架保留的清单文件名，本轮冻结适配器保持原样。
