# 最新规则发现修改：真实执行过程复盘

## 结论与覆盖

本轮实际测试的候选是 039d2f7，基线是其直接前版 0b68443；不是此前已撤回的 Python Code Agent。固定 GLM-5.3-flash、enabled / low、流式，规则功能以外的设置一致。

计划 12 次，实际尝试 10 次。第 10 次供应商响应缺少 message_stop，依据冻结协议停止，无自动重试；9 次完整用量、4 对用量完整的样本。该中断发生在文件修改前，不能归因于规则发现，也不能将其完整用量记为零。该样本已有 1,619 Tokens 确定记录，后续请求未知。

完整配对的 4 对中：基线 86,446 → 候选 89,464 provider Tokens，增加 3.49%；完整验收 3/4 → 4/4。请求数 29 → 28，但输入总量并未随请求数一起减少。不能将这一部分结果外推为完整 6 对或生产正确率。

## 确实起作用的部分

首轮目录重试题的新版过程：读根规则 → 沿导出链读源码 → 目标源码输出提示局部 AGENTS.md → 读取局部规则 → 修改 → 测试通过。最终满足局部规则要求的精确错误消息。

旧版两次同题均通过基本代码行为检查，但没有读取这份局部规则，也均未满足错误消息约定。这是“遗漏项目约定”，不能写成算法错误，也不能说拦截了越权修改。本轮 editPermissions 为空。

新版已完整结算的 4 次任务都在目标编辑前读取了根规则和适用局部规则。中断样本尚未编辑，不用于证明该能力失败。

## 发现的问题

### 1. 同一待阅读规则被重复提示

新版分页题连续读取 api、store、pagination 时，三个输出分别携带相同 src/AGENTS.md 提示，之后才阅读规则。当前实现只有“完整读过则不提示”，没有“同一轮已提示则合并”的状态，因此批量读取会重复消耗文本。

后续可尝试同一模型轮次合并提示，仍为未读规则保留后续提醒，并在规则更新、上下文压缩后重新确认。不能简单永久关闭第二次提示，否则首条提示被忽略或移出上下文后可能永远不再出现。

### 2. 工具选择错误仍存在

新版已结算任务中两次使用 write_file 修改已有源码，被拒绝后才改用 apply_patch；基线有一次。重试题读到了局部规则也没有避免该错误。

说明规则发现不等于工具能力理解。本轮样本太少，不能断言新功能导致误用增加。后续可单独测试更明确的已有文件反馈及工具语义，不混入当前已冻结实验。

### 3. 拒绝反馈引起一次额外寻找与重读

新版分页题在已有文件新建失败后，list_files src，再读了一次此前已读取的 pagination，才进行补丁。这与 SOURCE_MISMATCH 统一要求重新获取当前源码的反馈一致，但无法仅凭记录证明因果。现有文件已存在与读取证据真的过期应当区分，避免不必要恢复工作。

### 4. 阅读了接口，仍可能生成错误测试

新版分页题已读取 store 与公开测试，但新增的陈旧游标测试仅放入两条数据，默认页大小为两条，导致没有后续游标。之后将数据补为三条，重新测试通过。修复的是自己创建的测试，未修改受保护的已有测试，隐藏测试也通过；不是通过改旧测试掩盖源码错误。

基线也有新测试预期错误，包括错误地认为 100～200 没有水仙花数，以及分页测试对象 id 写错。说明新提示无法消除模型自身断言错误；普通任务 Token 下降 24.76% 不能直接归因为规则发现，其中混有测试修复轮次差异。

### 5. 当前发现时机有覆盖边界

启动仅发现根规则，目录规则在 read_file 时发现。模型如果绕过源码读取而直接创建或编辑深层目标，不保证发现该目录规则。确定性测试验证的是已实现路径，不能扩大为“所有编辑前必然加载所有规则”。

未来可单独评估编辑前的规则检查或轻量目录发现；它可能增加调用，需重新对照，不应直接强制每次编辑前重复读取全文。

## 保留意见

当前结果支持它能减少遗漏局部规则，但不支持把它宣传为 Token 优化。分页已完成的一对用量增加 27.40%，包括规则提醒、额外读取、工具误用及测试修复等共同影响；不能把全部增量算在重复提醒上。

暂不继续修改候选，也不补跑未知样本。优先建议下一轮只改“同轮提示去重”，之后再分别测试已有文件反馈与规则发现时机；等待用户审核本轮结果。

本轮完整回归 359/359 通过，零跳过。记录分析仅使用可观察工具事件、文件快照、独立测试与供应商用量，不导出或声称还原内部思维链。费用控制累计 1.179183 USD 中含 1 USD 未知样本预留；其余 0.179183 USD 是完整用量样本控制估算，非账单。
