# S5：按需反馈以改善测试修复效率

## 假设与范围

S4 的收益只能在验证成功后出现。本轮在验证失败时改进诊断反馈，尝试减少错误测试预期与原样重跑超时命令造成的往返。

候选 SDK 开关 `testRepairFeedback: true` 默认关闭，且依赖已启用的 `capabilityFeedback`。只改变两类失败反馈：

- 验证命令非零退出：对照任务约定和原有测试，凭证据修复实现或错误的新增测试预期；保留原有测试及用户改动，允许任务要求的测试修改，但不能为了通过而放宽必要检查。先运行相关小检查，再运行要求的测试集。
- 验证命令触发执行器命令期限：标记 `VALIDATION_TIMEOUT`、`retryable: false`，要求检查执行器、控制流和测试清理。超时本身不能判断是代码还是环境问题；取得新证据或作出相关变动后仍可重试。

没有新增自动命令、重试拦截、缓存、压缩、预算或权限规则。`retryable` 为诊断信息，不自动停止 Agent。原始错误内容、待验证状态、验证标准保持不变。网络超时、取消、权限错误和非验证诊断不采用新分类。

不添加固定系统提示或工具说明。未触发时请求保持原样；新增反馈本身可能消耗更多 Token，必须由真实实验验证是否被更少的修复往返抵消。没有触发的独立任务不能用于机制归因。

## 验证与冻结协议

专项覆盖关闭兼容、原始错误保留、断言修复建议、命令与网络超时区分、错误优先级、取消与权限、真实修复循环、实际命令超时、待验证状态、首次请求/参数一致，以及反馈总开关关闭。

基线使用 main `6a50dc5`，不包含已撤销 S1/S2/S3/S4。八道现有自编 Node.js 编码题，每版本三次，共 48 次；每次新工作区、同题交替先运行版本。固定 GLM-5.3-flash、enabled thinking / low effort、4096 输出、32768 上下文、4096 预留、24 工具尝试、256000 字节请求上限、ContextOS 和自动压缩配置。

每模型请求 90 秒、每任务 10 分钟；沿用相同的 120 秒命令期限和单次 15 秒验收期限。每次预留 1 USD，整组 8 USD；输入 0.8 / 输出 2.8 USD/MTok 作为保守预算核算，非账单证明。用量未知停止并保留预留，不付费重试；任务验收失败继续其余独立样本。

**付费前确定采用门槛**：48 次覆盖完整、用量全部已知；完整验收与独立代码行为均不得在总体或任何题型下降；所有尝试累计 provider Token 更低。代码行为指原有、新增和隐藏测试均通过，完整验收还包括保护文件和执行流程。双方通过子集单列，不替代全量。

付费前冻结源码、入口、任务清单与模型配置，验证初始/参考实现和固定工具定义指纹。记录新反馈触发次数、验证失败、命令超时和超时后无成功文件编辑的同命令重试次数；后者是轨迹计数，不自动判定重试无依据。

失败成本保留，图表成功均值不含失败，失败成本单独显示；未知不按零。无收益或质量下降即撤销运行时改动、保留实验记录。阶段结束等待审核，不开始下一阶段。每题三次仅为诊断性小样本，不证明统计显著性或生产泛化。

## 复现入口

每次使用新 run ID，保留历史结果；本地需要有上述基线和候选 Git 提交。

```sh
# 无模型调用：验证冻结版本、固定工具定义及初始/参考实现。
node scripts/compare-coding-s5.mjs --mode=prepare --run-id=s5-preflight-new

# 有限预算的真实付费对比，沿用用户 API 凭据。
node scripts/compare-coding-s5.mjs --mode=live --run-id=s5-live-new

# 运行结束后，检查首次请求/反馈指纹、审计私有加密日志、生成公开汇总。
node scripts/check-coding-s5-feedback.mjs s5-live-new
node scripts/audit-coding-s5-feedback.mjs s5-live-new
python scripts/report-coding-s5.py s5-live-new
```

审计通过 `--completed-only` 可检查已结束样本，输出明确标记 partial 的私有文件；公开最终汇总不接受该文件。

## 解释边界

本轮只在已发现的验证失败或执行器超时后介入。若模型自写测试没有覆盖真实缺陷，未报告失败时不会触发，不能声称自动提高边界覆盖率。超时分类的真实收益需要出现实际超时样本；专项中的受控超时只能证明分类和待验证状态正确。

更长反馈仍可能增加后续输入或引发更多检查；反馈后的修改次数不单独证明修复质量或 Token 收益。相同模型的独立生成路径有波动，未触发任务的差异尤其不能归因于本方案。

## 撤销与回归

第三轮区间合并题完成后，基线完整验收 3/3、候选 2/3，逐题质量门槛已无法满足。随即将 `src/agent.mjs` 和 `src/tool-feedback.mjs` 恢复到基线，并删除仅为候选增加的七项专项测试；冻结的真实对比继续完成，未修改运行中的引擎或付费入口。

恢复后全量测试 **320/320 通过，无跳过**；`git diff --quiet 6a50dc5 -- src` 确认运行时源码与基线一致。候选实现与专项测试保留在 `158ca4c` 提交供复查，本 PR 最终不增加生产开关。

## 已复核的行为案例

- 分页题第一轮候选新增了快照数组必须与原数组身份不同的断言，但任务要求保持现有 `snapshot()` API，并未要求复制数组。收到建议后，只删除了这个错误新增断言，保留内容不变检查，最终验收通过。这是合理修正新增测试，但该次用量仍高于对应基线，不能据此宣称节省。
- 区间合并和调度题第一轮候选修改了受保护的原有测试。两次均未触发 S5 反馈，因此必须记录为质量失败，同时不能把违规直接归因于未执行的新建议。
- CSV 第二轮双方自写测试通过，却都未覆盖隐藏检查中的空字段边界，候选实际返回 `[]`、预期为 `[['']]`。没有可见验证失败时，本机制不会介入；更长的错误提示无法替代测试覆盖。

这些案例只解释观察到的行为。独立生成的对应运行并非在同一失败状态下的反事实实验，不能用总差额量化某一句反馈的因果作用。

## 最终结果与决定

完成八题、三轮、两版本共 **48 次真实运行**，全部用量已知，源码冻结核验通过，无付费重试。报告与 PNG/SVG 图见 [S5 实验报告](../benchmarks/reports/coding-s5-paired-glm-20261016-v1/README.md)。

- 全部尝试累计 provider Token **678,865 → 735,468，增加 8.34%**。包含失败尝试、缓存输入和输出中的思考，不重复累加缓存或思考。
- 完整验收 **22/24 → 21/24**；独立代码行为 **23/24 → 23/24**。区间合并、异步调度完整验收分别由 3/3 降至 2/3；依赖图由 2/3 升至 3/3，不能抵消逐题下降。
- 双方均通过的 20 对样本 Token 也增加 **2.12%**。三轮总差依次为 **−0.64%、+3.79%、+24.01%**，没有稳定收益。
- 新反馈在候选 **10/24** 次任务中触发，共 **15** 次。实时观察器与加密日志审计计数完全一致。真实命令超时 **0** 次，不能宣称超时诊断节省。
- 总请求 **194 → 198**；全部成功测试编辑 **37 → 46**，源码编辑 **42 → 35**。这说明本轮没有减少总体往返；编辑数量本身不是质量或因果指标。

输入 Token 增加 54,041，输出增加 2,562；新增反馈更长且后续仍随历史发送，额外检查和不同模型轨迹都可能放大输入。实验没有隔离每个因素的因果贡献，不能把 8.34% 全部归因于反馈文字。

**不采用 S5 运行时改动。** 最终源码保持基线，保留冻结实现、复现工具和失败结果供审核；本阶段结束，不启动 S6。
