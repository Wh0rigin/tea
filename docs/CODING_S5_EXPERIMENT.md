# S5：按需反馈以改善测试修复效率

## 假设与范围

S4 的收益只能在验证成功后出现。本轮在验证失败时改进诊断反馈，尝试减少错误测试预期与原样重跑超时命令造成的往返。

候选 SDK 开关 `testRepairFeedback: true` 默认关闭，且依赖已启用的 `capabilityFeedback`。只改变两类失败反馈：

- 验证命令非零退出：对照任务约定和原有测试，凭证据修复实现或错误的新增测试预期；保留原有测试及用户改动，允许任务要求的测试修改，但不能为了通过而放宽必要检查。先运行相关小检查，再运行要求的测试集。
- 验证命令触发执行器命令期限：标记 `VALIDATION_TIMEOUT`、`retryable: false`，要求检查执行器、控制流和测试清理。超时本身不能判断是代码还是环境问题；取得新证据或作出相关变动后仍可重试。

没有新增自动命令、重试拦截、缓存、压缩、预算或权限规则。`retryable` 为诊断信息，不自动停止 Agent。原始错误内容、待验证状态、验证标准保持不变。网络超时、取消、权限错误和非验证诊断不采用新分类。

不添加固定系统提示或工具说明。未触发时请求保持原样；新增反馈本身可能消耗更多 Token，必须由真实实验验证是否被更少的修复往返抵消。没有触发的独立任务不能用于机制归因。

## 验证与冻结协议

专项覆盖关闭兼容、原始错误保留、断言修复建议、命令与网络超时区分、错误优先级、取消与权限、真实修复循环、实际命令超时、待验证状态、首次请求/参数一致，以及反馈总开关关闭。

基线使用 main `6a50dc5`，不包含已撤销 S1/S2/S3/S4。八道现有自编 Node.js 编码题，每版本三次，共 48 次；每次新工作区、同题交替先运行版本。固定 GLM-5.3-flash、enabled thinking / low effort、4096 输出、32768 上下文、4096 预留、24 工具尝试、256000 字节请求上限、ContextOS 和自动压缩配置。

每模型请求 90 秒、每任务 10 分钟；沿用相同的 120 秒命令期限和单次 15 秒验收期限。每次预留 1 USD，整组 8 USD；输入 0.8 / 输出 2.8 USD/MTok 作为保守预算核算，非账单证明。用量未知停止并保留预留，不付费重试；任务验收失败继续其余独立样本。

**付费前确定采用门槛**：48 次覆盖完整、用量全部已知；完整验收与独立代码行为均不得在总体或任何题型下降；所有尝试累计 provider Token 更低。代码行为指原有、新增和隐藏测试均通过，完整验收还包括保护文件和执行流程。双方通过子集单列，不替代全量。

付费前冻结源码、入口、任务清单与模型配置，验证初始/参考实现和固定工具定义指纹。记录新反馈触发次数、验证失败、命令超时和超时后无成功文件编辑的同命令重试次数；后者是轨迹计数，不自动判定重试无依据。

失败成本保留，图表成功均值不含失败，失败成本单独显示；未知不按零。无收益或质量下降即撤销运行时改动、保留实验记录。阶段结束等待审核，不开始下一阶段。每题三次仅为诊断性小样本，不证明统计显著性或生产泛化。
