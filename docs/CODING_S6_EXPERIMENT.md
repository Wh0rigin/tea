# S6：版本校验的完整文件替换

## 假设与候选

P0 在 S5 基线中发现 22 次已有文件写入拒绝，之前均有完整读取，只有一次随后再次读取。候选针对拒绝后重新构造编辑操作的往返，不把关联窗口的 63,425 Token 当作可节省量。

SDK `versionedWrite: true` 默认关闭；不增加 CLI 开关。扩展已有 `write_file` 的可选 `expected_sha256`，未提供该参数时仍只创建新文件。版本号复用读取回执的 SHA-256，无额外读取元数据；模型必须显式请求完整替换。

替换要求完整未截断、未脱敏的单文件读取；内部额外保存原始字节哈希和文件身份，不保存新的全文副本。只有读取结果被加入会话后才确认授权，取消未交付结果不授权。缓存有 32 条上限，不持久化；补丁、原有证据清空、重置、GC 和新进程恢复使其失效，需重新读取。空文件、中文、CRLF 和 BOM 均覆盖。

写入前核对路径父目录、文件身份、原始哈希、普通模式位和硬链接数。禁止符号链接父目录、硬链接、只读文件、敏感路径和缺失文件替换。沿用文件创建能力开关和修改后验证。新增参数及能力说明有固定开销，需要付费实验核对，不能只计算被省掉的拒绝。

## 文件系统边界

同目录暂存、同步后再次核对版本并 rename；暂存、取消、观察到的提交前修改、rename 失败均保留目标并清理暂存。不使用删除原文件强制替换的回退。普通模式位保留。

这是原子内容发布，**不是针对不合作外部写入者的原子 CAS**。最终核对到 rename 之间仍有并发窗口；没有宣称解决该竞争。rename 更换 inode，不能宣称保留原文件所有者、自定义 ACL、扩展属性或文件监视器的全部语义。候选仅用于实验、默认关闭；生产采纳还需审查这些语义，不以 Token 收益替代用户变更保护。
