# 编码流程提示、同文件批量修改与验证闭环

本轮参考本机 Pi 0.87.1 的工具使用指导，改善 TEA 的具体执行步骤。基线为 `b400577185f0b224850540cc9289672f62450f33`。实现独立编写；没有引入 Pi 运行时依赖。

## 1. 按实际工具组织提示词

`src/prompts.mjs` 集中构建身份、工作流程和结果汇报。只为已暴露的工具加入阅读、创建、批量编辑和验证指导，同一条指导不重复添加。

修改流程明确为：阅读适用规则和相关源码，完成一组相关修改，再运行对应检查。失败后继续修复并重跑尚未通过的命令。避免将“修改后验证”误解为每次替换都必须立即调用一次测试。

权限、命令语法和平台限制继续由工具执行器落实。宿主的 `ToolContext / ToolSpec / ToolService` 不进入模型提示词。

## 2. 一次修改同一文件的多个位置

`apply_patch` 新增 `edits` 参数，保留原先的单次 `search` / `replace` 调用方式，两种形式不能混用：

```json
{
  "path": "src/example.mjs",
  "edits": [
    { "search": "const limit = 3;", "replace": "const limit = 5;" },
    { "search": "const retry = 1;", "replace": "const retry = 2;" }
  ]
}
```

- 每次 1 至 32 项，全部匹配修改前的原始文件；不依次搜索前一项的替换结果。
- 每项必须唯一匹配，匹配区域不能重叠。任一项失败，整次调用都不写入。
- 保留未修改文本的换行和 Unicode。结果必须为有效 UTF-8 文本且不超过 160 KB。
- 需要审批时，一次展示全部替换，审批内容不可变；拒绝路径规则继续生效。
- 审批后重新检查目标和源码；期间发生手动修改则拒绝覆盖，提示重新读取。
- 终端默认展示前三处替换，完整工具输入可以通过 `/tools N` 查看。

这里的保证是全部预校验后单次写入；没有宣称跨进程并发编辑隔离或断电安全的文件事务。

## 3. 未解决的验证失败独立保留

原问题是最近一次检查覆盖全局状态：全量测试失败后，某个局部测试通过，也可能把任务标为完成。

现在保存尚未解决的验证命令。某条命令失败、未完成或执行零项测试时，其他命令成功不能将它清除。修复后，同一命令成功才清除该条记录；全部记录清除后，才允许通过验证完成任务。新的源码修改仍会恢复待验证状态。

命令身份使用执行器相同的参数解析方式，忽略命令外部的空白及等价引号，保留参数顺序、参数值和引号内空白。例如，`node --test a.test.mjs` 与 `node   --test "a.test.mjs"` 等价；`node --test` 与 `node --test a.test.mjs` 不等价。

工具反馈和结束前提醒会指出尚待重跑的命令。记录经过加密会话持久化、恢复、自动压缩和 GC 检查点继续保留；`/new` 清空对话时不会清掉这些工作区验证义务。

限制：暂不自动证明不同命令之间的测试覆盖包含关系。改用另一个等价测试入口，也需要补跑原先失败的命令。这是一种保守完成条件，并不能保证首次选择的测试范围已经覆盖所有需求。旧会话没有记录的历史失败也不会被追溯推断。

本轮没有新增付费请求。真实模型的 Token 和解题收益尚未判定；固定定义增加的开销需要靠减少实际执行轮数抵消。
