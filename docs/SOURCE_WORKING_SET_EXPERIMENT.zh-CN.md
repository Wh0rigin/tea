# 近期源码工作集实验

参考Pi在摘要前保留近期原文的思路，调整TEA专有ContextOS的过早证据引用化。不是复制Pi工具或声称与Pi相同。

默认关闭。TEA_CONTEXTOS_WORKING_SET_BYTES=24000时，最多从当前请求历史选择最近8个源码文件的最新含行号证据片段，额外保留合计不超过24,000 UTF-8字节。没有恢复已被checkpoint移除的原文，源码版本仍逐次校验；原有规则、错误、近期轮次和修改文件保护不变。

离线示例使用自编确定性消费者：需要旧源码时，基线必须召回一次；候选已保留原文，无需召回。首请求5,921→8,363字节（增加）；取得相同证据的完整路径20,155→8,363字节。这里是序列化字节，不是真实Token，消费者规则也不能证明真实模型会少调用。

完整回归452通过、1跳过、0失败；证据专项15/15。拟进行两个Helm候选运行，与同端点历史main的两次结果比较，记录所有失败/未知；Pi不重测。这是已见任务的筛选，不是无偏因果或通用收益结论。每次10USD总20USD保守控制额度（非实际账单），128请求、4096工具、900秒单请求、1800秒Agent时限。未知用量保留整题分配且不重试。

采用门槛：两次均正常完成、用量完整；官方至少1/2通过、原有用例不下降；候选工作集机制实际生效且总用量低于历史Helm两次合计2,573,652 Token。未达门槛不默认采用；通过也只构成进一步验证的依据。结束后停供审核，不自动合并。
