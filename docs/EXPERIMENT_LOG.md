## E2 — V1 初始文件清单筛选（离线筛查）

- 假设：每次请求都发送排序后的前 160 个文件名会重复携带大量无关路径；按任务词和路径重合度选出短名单，完整列表/代码搜索仍由工具按需查找。
- 改动：新增路径打分和初始 inventory，默认保留最多 8 条；固定显示适用的 `AGENTS.md` 及 README/package 清单；工具仍能扩展发现。遥测只保存数量、策略和路径列表 SHA-256。
- 回放：23 条自编轨迹，13 条带有 26 个标注相关路径的大型合成仓库；baseline 估算 13,431 Token、命中 1/26；词面筛选 cap=8 估算 2,129、命中 21/26。成对估算不是服务商计费 Token。
- 限额扫描（每个仓库含 3 个固定提示文件）：cap=2、3 命中 0/26；cap=4 命中 13/26；cap=6、8 命中 26/26。选默认 8 给额外路径留空间；这只证明当前合成清单的召回，不代表真实仓库正确率。
- 决定：继续尝试针对描述与路径措辞不一致的查询扩展；不单独准入或提交。

## E3 — 低重合时的领域同义词扩展（离线筛查）

- 观察：词面短名单在“登录状态超时”“重新生成凭证”等释义中漏掉 `session/expiration`、`auth/refresh` 路径。
- 改动：仅当所有非固定路径的词面最高分低于 5 时，加入一组小型领域同义词（例如 sign-in/session、renew/refresh、obsolete/stale、repeat/retry）；固定名单上限不变。该触发条件和是否触发都记入离线诊断/本地运行 Ledger。
- 成对筛查：纯词面筛选 2,129 估算 Token、命中 21/26；自动扩展 2,106、命中 26/26，13 条定位样本中有 4 条触发。与纯词面候选的估算差值 95% Bootstrap 区间为 `[-3.83, 0.61]`，包含零；当前样本下多找到 5 个标注路径，估算开销几乎不变。
- baseline 对合并 V1：23 条合成轨迹，估算 13,431 → 2,106（−84.32%），标注路径召回 1/26 → 26/26；95% Bootstrap 候选−基线区间 `[-679.57, -304.78]` Token。
- 单独重复读去重：本轮 23 条轨迹下估算下降 0.22%，95% 区间 `[-3.91, 0.00]`；没有足够证据说明它单独有实际收益。
- 验证：`npm test` 22/22 passed；`git diff --check` 通过。Replay 不调用模型、不给代码任务打分、也不测服务商用量，所以全部结果不具备优化门禁资格；未提交、未推进 `main`。

## E4 — 大量日志的有界返回（真实命令，离线）

- 发现：原工具 stdout/stderr 总量超过约 28k 时杀进程，随后只返回开头；正确或失败测试均无法得到完整退出状态和尾部断言。
- 改动：有界内存保存各流头尾/完整 SHA-256；成功每流 2k、失败 6.5k 字符；输出量不杀进程，超时仍结束 Windows 进程树。
- 实际命令比较：固定约 165k 字符日志，原版两项均 SIGTERM；候选完整取得 exit=0/1，成功返回 1,899（−86.47%），失败返回 6,448（−54.06%），均保留尾部结果。
- 延迟：候选约 1.66 秒，原提前中止约 0.37 秒，不构成速度改进证据。报告 `benchmarks/results/command-output-wKAWEz/report.json`。
- 决定：保留正确性与体积改善候选，provider Token 尚未测，不准入。

## E5 — 执行与计量缺陷修复

- 实际 Runtime 集成检查发现任务文本被错误传作 hash 算法名，启动即失败；改为 SHA-256 update(task)。
- Git 诊断/help/collect-only/Node 零通过测试不能满足编辑后验证；新编辑或后续验证失败恢复待验证，run_shell 中真正测试也计入。
- SSE 连续解码 UTF-8、消费尾部无换行事件；总输入包含普通/缓存读/缓存写，不重复累计流式计数。
- 缺失/无效/中断 usage、账本写失败不发布完整实测总量；保留已报告下界和本地保守费用预留。缓存写默认 2× 基础费率并非 Packy 实际账单。
- 安全运行 ID、防旧账本混入、导出 Live API 的有限价格/预算/整数上限、同 adapter 并发请求保护已覆盖。
