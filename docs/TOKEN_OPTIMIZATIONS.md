# Token 消耗优化与改进点记录

更新日期：2026-10-11。

本文逐项记录项目实际采用或正在实验的方法，包括原理、实现位置、开关、收益和限制。后续新增优化应继续更新本文，并链接对应实验报告。

## 一、先明确测量口径

- **实际模型 Token**：由服务商 usage 返回，包含输入、输出和缓存输入。目前尚未完成真实模型配对测量，因此没有已验证的实际 Token 降幅。
- **启发式 Token 估算**：按文本计算的诊断值，不是模型原生 tokenizer 的计数。
- **工具输出字符**：工具返回文本的长度；实现使用 JavaScript 字符串长度。
- **输入字节**：序列化 `system/messages/tools` 后的 UTF-8 字节数，不包含完整 HTTP 请求字段，也不等于网络发送量或计费 Token。

以下百分比来自不同样本和不同口径，**不能直接相加，也不能据此计算累计真实 Token 节省**。脚本化补丁的验收通过率不等于模型任务成功率。

## 二、逐项改进记录

### 01. 按任务相关性筛选初始文件清单

- **阶段与状态**：V1 已提交，默认启用。
- **浪费来源**：每轮历史都携带较长的初始文件清单，其中大量路径与当前任务无关。
- **方法**：将原先最多 160 个初始路径，改为默认最多 8 个任务相关路径；按任务词和路径重合度排序，优先放入 `AGENTS.md` 和根目录项目说明/包清单。候选数量仍受上限约束。
- **恢复方式**：清单明确标注是否完整；代理可继续调用 `list_files`、`search_code`，不把短名单当作完整仓库。
- **实现**：[context.mjs](../src/context.mjs)、[tools.mjs](../src/tools.mjs)。
- **配置**：默认 `--context-strategy v1`；`--initial-file-limit N` 范围 1–250；`baseline` 使用原始清单策略。
- **结果**：23 条合成回放中，纯词面筛选 cap=8 的估算输入为 2,129，对照为 13,431；加入第 02 项后为 2,106，合并降幅 **84.32%**。该数值包含当前回放中的其他上下文机制，不应归为此项单独的实测收益。
- **限制**：仅是合成回放估算；候选上限过小会漏文件，当前样本中 cap=2、3 未命中标注路径。

### 02. 词面匹配弱时扩词，并在模型找到真实名称后学习会话映射

- **阶段与状态**：V1 的固定扩词已提交；会话映射学习已接入当前工作区，尚未测量收益。
- **浪费来源**：用户描述和文件路径措辞不同，可能造成定位失败和后续重复探索。
- **方法**：初始文件筛选仍在词面分数低于阈值时使用少量手写同义词，例如 `renew/refresh`。若这些线索没有帮助模型定位，模型继续调用搜索和读取工具。实际 `search_code` 未命中后，运行时才提供 `remember_term_mapping` 工具；模型找到对应的真实代码名称后，可提交“未命中的查询 → 真实名称”映射。
- **白话示例**：用户说“凭证续期”，搜索没有结果。模型继续查代码，读到 `function rotateCredential()` 的源码，并判断它确实负责这件事，才把“凭证续期 → rotateCredential”存入本次运行的词表。以后再次搜索“凭证续期”，会同时搜索 `rotateCredential`。
- **保存条件**：原查询必须实际搜索失败；目标名称必须完整出现在通过 `read_file` 展示过的源码行中，且保存时源码未变。模型负责确认它是实际对应名称，而不是猜测或注释、字符串中的偶然提及；运行时只检查名称出现和证据有效，不声称证明声明语法或语义对应。
- **会话范围与失效**：单次命令的词表保存在该任务内存中；交互终端通过 `createAgentSession` 在追问之间复用。`/new` 清空词表和对话，退出后不保存，不写入全局手写词表。最多保存 32 个查询，每个最多 4 个映射；复用前检查来源文件哈希，文件修改或删除后丢弃对应映射。不再用固定的 JS/Python 声明关键词限制语言；支持普通名称及带点、冒号、连字符、斜杠的限定名称。
- **模型与开销**：由现有任务模型继续定位，不新增专门的查询改写模型请求。学习工具仅在搜索失败后加入可用工具；发现过程、工具调用及新增工具定义仍有 Token 开销，并计入正常任务记录。
- **实现**：[context.mjs](../src/context.mjs)、[tools.mjs](../src/tools.mjs)、[agent.mjs](../src/agent.mjs)。
- **配置**：`v1` 自动扩词；`v1-inventory` 可作为不扩词对照，`v1-inventory-expanded` 为始终扩词对照。
- **结果**：历史固定扩词实验：纯词面候选 → 自动扩词，估算 2,129 → 2,106；标注路径召回 **21/26 → 26/26**。13 个定位样本中 4 个触发扩词。这些数字不代表新增会话学习的收益。
- **限制**：单项估算差值的 95% 区间包含零，不能说已证明独立 Token 收益。当前直接证据是合成样本中定位召回改善，尚未测得实际探索调用减少量。

### 03. 按行读取源码、限制搜索结果、分页发现文件

- **阶段与状态**：基础工具已有，V1 补充了分页及截断证据保护；没有独立收益实验。
- **浪费来源**：为了查看局部逻辑而发送整个文件，或一次返回过多路径和搜索命中。
- **方法**：`read_file` 接受 `startLine/endLine`；`search_code` 默认最多 30 个结果、上限 80；`list_files` 支持 `offset/maxFiles` 分页。单次读取结果受工具输出上限约束，截断会明确说明。枚举可翻到第 700 个文件之后；枚举和搜索支持 `path` 缩小目录范围，`includeOmitted` 可探索普通被排除目录。搜索返回扫描范围、文件数和字节数，未命中不再表述为整个仓库不存在。
- **实现**：[tools.mjs](../src/tools.mjs)。
- **使用示例**：`read_file({path: 'src/session.mjs', startLine: 40, endLine: 90})`。
- **结果**：尚未独立测量百分比。
- **限制**：未指定行范围时仍可能读取整文件；代理需要主动选择范围。被截断的范围不能当作完整证据缓存，后续必须补读遗漏部分。搜索和枚举也有扫描边界，不能保证任意大型仓库的完整发现。

### 04. 相同源码范围重复读取时返回证据引用

- **阶段与状态**：V1 已提交，默认 `v1` 启用。
- **浪费来源**：同一文件、同一行范围被重复读取，全文多次进入后续请求历史。
- **方法**：保存路径/行范围与脱敏后源码 SHA-256 的对应关系；只有该范围之前完整发送过且源码哈希未变，才返回短 `evidence ref`。文件变化时发送新证据。
- **实现**：[tools.mjs](../src/tools.mjs)。
- **配置**：`v1-dedup` 可用于单独观察去重；`baseline` 不启用；`v1` 包含去重。
- **结果**：最终 23 条回放中的单项估算下降 **0.22%**，95% 区间包含零，收益不明确。早期较小回放曾得到 3.84%，不以该早期数值替代扩展样本结果。
- **保护**：短引用必须比原文更短；截断范围不允许引用为完整证据；源码修改后哈希刷新；V2 不删除引用依赖的源码历史。
- **限制**：只省第二次及后续工具返回内容，第一份源码仍保留；不是删除原始源码或只发送哈希。

### 05. 过滤依赖、生成文件和不适合读取的文件

- **阶段与状态**：基础工具已有，无独立优化提交或收益实验。
- **浪费来源**：依赖和构建产物可能淹没仓库清单与搜索结果。
- **方法**：一般枚举和搜索跳过 `.git`、`.tea`、`node_modules`、`vendor`、`dist`、`build`、`coverage`、`.next` 等目录，默认跳过这些目录；需要时可使用 `includeOmitted`。未知后缀通过 UTF-8/NUL 检查识别文本，直接读取不再依赖语言后缀白名单；读取大小限制仍保留。
- **实现**：[tools.mjs](../src/tools.mjs)。
- **结果**：尚未独立测量百分比。
- **限制**：属于有界工具与安全设计。凭据过滤主要用于保护敏感信息，不能把安全过滤量写成已验证的 Token 收益。

### 06. 使用精确局部补丁，避免返回整个修改后文件

- **阶段与状态**：基础工具已有，无独立收益实验。
- **浪费来源**：修改少量代码时，模型生成和工具回传整份文件会产生不必要文本。
- **方法**：`apply_patch` 接收路径、唯一匹配的 `search` 片段和 `replace` 片段，仅替换该位置，工具返回简短回执。
- **实现**：[tools.mjs](../src/tools.mjs)、[agent.mjs](../src/agent.mjs) 中的系统提示。
- **结果**：尚未独立测量输出 Token 或工具字符降幅。
- **限制**：上下文不足时仍须读取相关源码；不通过少读必需代码或跳过修改后验证换取节省。

### 07. 长命令日志保留头尾，并区分成功与失败的返回预算

- **阶段与状态**：V1 已提交，默认启用。
- **浪费来源**：测试打印大量中间日志；原工具还会因输出过多提前杀进程，丢失退出状态和尾部错误。
- **方法**：分别保存 stdout/stderr 的有界头尾和完整流哈希；较多空间留给结尾。成功命令每流返回预算为 2,000 字符，失败命令为 6,500 字符，最终工具输出上限为 14,000。输出量不会中止进程，超时仍会终止。
- **实现**：[output.mjs](../src/output.mjs)、[tools.mjs](../src/tools.mjs)。
- **结果**：相同约 165k 字符日志的真实命令实验中，成功返回 **14,035 → 1,899（−86.47%）**；失败返回 **14,035 → 6,448（−54.06%）**。候选正确取得 exit=0/1，并保留失败断言和总结。
- **限制**：这是工具返回字符降幅。原工具提前退出，不能据此宣称延迟提升或做等价完整执行的模型 Token 比较。中间日志会省略，完整哈希不能恢复被省略文本，需要时应重新获取诊断。

### 08. 只在请求视图中压缩较旧的工具历史

- **阶段与状态**：V2 已提交，需显式启用；默认仍为完整历史。
- **浪费来源**：长发现结果和成功日志已经返回一次，却在每个后续请求中再次发送。
- **方法**：将较旧且足够长的 `list_files`、`search_code`、允许的成功验证/只读 Git 结果，替换为带原调用 ID、完整输出 SHA-256、长度和恢复说明的记录。完整原始历史仍保留在运行时内存中，不调用模型生成总结。
- **保留内容**：至少最近两轮工具结果；所有源码读取与引用、补丁回执、失败和零测试输出、用户指令、assistant 原始文本/工具输入/思考块/签名。重复 ID、孤立或错误配对的结果保持原样。
- **实现**：[memory.mjs](../src/memory.mjs)、[agent.mjs](../src/agent.mjs)。
- **配置**：`--history-strategy compact-tools --history-keep-recent 2`；保留轮数范围 2–24。
- **集成结果**：重复长日志压力轨迹中，累计准备输入 **1,694,687 → 1,340,431 UTF-8 字节（−20.90%）**，含恢复说明开销；两侧脚本化验收各 **12/12**。普通任务的收益为 **0%**，不触发压缩。
- **辅助结果**：7 条轨迹、79 个成对请求，使用另一份较短系统提示的辅助输入字节减少 **54.02%**；保留四轮时减少 **37.09%**。这些辅助数值与集成结果是不同口径。
- **限制**：压力轨迹是人工重复调用，脚本适配器没有执行服务商预算预检；部分输入超过默认 guard。尚未测真实模型 Token、重新获取被省略信息的额外调用或任务质量。

### 09. 压缩或引用没有收益时，回退为原文

- **阶段与状态**：短引用保护已随 V1 提交；整轮压缩回退随 V2 提交。
- **浪费来源**：摘要、哈希和恢复说明可能比短原文更长，导致“优化”反而增加输入。
- **方法**：重复读取引用只有更短才使用；历史结果替换同时比较序列化字符和 UTF-8 字节。代理再计入恢复系统提示，要求整轮字节、字符和启发式估值均下降，否则退回原始请求。
- **实现**：[tools.mjs](../src/tools.mjs)、[memory.mjs](../src/memory.mjs)、[agent.mjs](../src/agent.mjs)。
- **结果**：普通 runtime 候选原始/准备输入均为 **279,315 字节，0% 变化**；短读取、短验证、普通短成功日志辅助轨迹也没有额外体积增长。
- **限制**：属于防止负优化的保护，不是第 08 项之外的另一份独立收益；估算下降仍不保证原生 tokenizer 计数下降。

### 10. 提示模型避免重复全文，并配置输出与调用上限

- **阶段与状态**：基础运行时已有；无独立收益实验。
- **浪费来源**：模型重复复述已经给出的源码/日志，或持续生成无必要文本和调用。
- **方法**：系统提示要求在有证据支持时使用简短总结，避免复述完整文件和旧工具输出。默认最大输出为 1,200 Token，工具调用上限为 24，可通过配置调整；响应因上限截断时不能标记为完成。
- **实现**：[agent.mjs](../src/agent.mjs)、[config.mjs](../src/config.mjs)、[model.mjs](../src/model.mjs)。
- **结果**：尚未测量模型是否遵守提示，或上限对成功率和总 Token 的影响。
- **限制**：上限是资源约束，不是已验证优化。过小的上限可能截断必要工具调用或解释，也可能增加后续重试成本。

### 11. 基于验证反馈的双向推理档位路由

- **阶段与状态**：V3 未提交候选，独立模块；尚未接入真实模型运行循环。
- **浪费假设**：整个任务固定使用较高档位，可能在已解决问题后的简单阶段继续付出过多推理开销；只升级不降级也可能持续高开销。
- **方法**：同一源码和验证命令连续出现两次新失败时考虑升级；当前源码有两次不同 attempt 的有效成功验证时考虑降级。支持升级、降级、保持，至少保持两步；编辑和源码变化使旧验证过期，并保留验证预算。
- **实现**：[policy.mjs](../src/policy.mjs)、[policy-experiment.mjs](../scripts/policy-experiment.mjs)。
- **本地结果**：13 条声明轨迹 × 4 种策略，共 240 个观察步；双向策略 4 次升档、5 次降档，保护违例为 0。零测试、Git 成功、旧 attempt、源码往返变化等负例已覆盖。
- **限制**：轨迹使用模拟状态，预算为抽象单位。没有运行真实模型，不知道实际推理 Token 是否下降，也不能宣称降档后模型正确率不变。

### 12. 校验本次输出上限和思考预算，阻止无效请求

- **阶段与状态**：V3 未提交候选。
- **浪费来源**：输出上限覆盖被忽略、超过配置上限，或思考预算与本次上限不一致，可能产生无效请求和恢复开销。
- **方法**：显式 0、无效值和超配置上限在请求前拒绝；普通 enabled thinking 预算按本次输出上限推导，不适用的小上限提前拒绝。不自动重试。
- **实现**：[model.mjs](../src/model.mjs)、[request-budget-experiment.mjs](../scripts/request-budget-experiment.mjs)。
- **本地结果**：父版与候选的实际适配器连接本地严格 HTTP 合约服务，9 个用例中非法提交 **6 → 0**，候选预期检查全部通过。
- **限制**：本地服务不是模型服务商，合约检查不能证明桥接兼容性；这不是实际 Token 下降百分比。

## 四、哪些改动不应算成 Token 优化

- SSE UTF-8 解码、结束事件处理、任务哈希修复：运行正确性修复，没有独立 Token 收益数据。
- 缓存输入归一化、未知用量设为 `null`、账本写入完整性：计量修复，不能把以前漏计的 Token 当作优化。
- 费用预留、超时、验证后置条件、独立验收：资源与质量保护，不代表每个任务消耗更少。
- 默认日志只存哈希和计数：减少本地日志原文保存，**不会因此减少发给模型的上下文**。

- 主动 prompt cache 配置：当前只是缓存 usage 计量与费用预留，没有已验证的缓存命中优化；缓存折扣也不等于原始 Token 消耗下降。

## 七、泛化能力检查（2026-10-11）

### 本轮已修改

- **02 会话词表**：移除仅支持少数语言声明关键词的校验，改为真实源码行中的完整名称证据。模型判断语义，运行时验证已读证据与源码一致。代价是运行时不能自动排除注释中的偶然提及，不能把出现检查当作声明证明。
- **01/03 文件发现**：初始清单明确说明最多 700 路径的索引边界；分页不再永久止于 700。枚举和搜索支持按目录继续探索。单次搜索仍有资源上限，返回范围和计数，避免把部分搜索未命中当成仓库无对应功能。
- **05 文件过滤**：未知语言后缀采用文本内容检查；新增 `includeOmitted` 探索普通隐藏、依赖或生成目录。凭据过滤、工作区边界和 Git 元数据排除仍保留。

### 其余逐项检查

- **01 排序**：依赖名称重合和固定项目清单名称，无法理解任意用户描述。短名单只是入口；无关候选需要模型继续发现。初始清单也可能被固定项目文件占满，尚未实现内容级相关性排序。
- **02 固定扩词**：仍只是初始提示，不作为完整语义覆盖；会话学习只帮助本次运行中再次使用相同查询，不保证新的不同说法自动命中。
- **03 大文件/编码**：160 KB、深度 12、UTF-8 限制仍可能漏掉实际源码；本轮没有实现流式大文件读取及其他编码解码。
- **04 读取引用**：哈希和完整范围判断不依赖业务领域，可继续使用；修改后需要重读。
- **06 局部补丁**：不依赖语言，但要求片段唯一；重复代码需增加上下文，不应猜位置。
- **07 日志头尾**：不依赖测试框架，但会省略中间错误。完整流哈希无法恢复内容；尚未实现完整日志按需检索，不能保证诊断完整。
- **08 历史压缩**：不依赖业务关键词，但“可重新获取”的结果可能随仓库或命令变化；已保留原历史和源码，恢复后的证据必须重新判断。
- **09 收益回退**：按当前请求尺寸判断，比固定任务规则更通用；仍缺原生 tokenizer 与重新发现开销的测量。
- **10 固定预算**：复杂任务、不同语言或模型可能需要不同输出/调用预算；可配置不等于自动适应，预算耗尽不得视为完成。
- **11 档位路由**：连续成功/失败次数来自预设规则，验证命令识别偏向 Node/Python；未接入运行循环，未证明跨语言或仓库质量。
- **12 请求预算**：依赖当前提供商协议和适配器能力；不能直接推广到其他模型或桥接服务。

### 尚需完成的泛化证据

早期修改阶段仅做语法与差异检查；随后完整确定性回归达到 128/128，并完成第九节的自编样本 Live 对比。后续仍应使用未参与调参的仓库、不同语言/自然语言描述、大文件和不同测试框架，比较定位成功率、修改正确率、额外探索成本及原生 Token；保留失败和负收益。当前不能声称“已保证泛化能力”。


## 八、交互终端与 Token 边界

新增交互界面复用现有运行循环，展示工具和用量不新增模型请求。连续对话会发送保留的历史，因此不能宣称交互模式本身降低 Token。初始清单仅在会话首轮（或 `/new` 后）提供，证据引用和可选历史压缩可继续使用。费用和累计输入预算通过同一适配器跨轮保持，不因 `/new` 重置；中断后的不确定请求保留费用预留，未知用量显示问号。终端演示为脚本化只读轨迹，没有模型用量和性能结论。

## 九、真实服务商 Token 验证（2026-10-11）

- GLM-5.3-flash、enabled/low、4,096 输出上限，TEA/Pi 原生工具与提示保持各自配置；每组相同固定仓库、任务和共同网关。
- 64,000 字节输入保护下完整 9 组：TEA/Pi **168,282/161,046 Token**，TEA **多 4.49%**；验收 **9/9 对 7/9**，含两次 Pi 上限失败。双方通过 7 组子集少 25.44%，单列且不当作全体收益。
- 全部 3 类大型任务另以 80,000 字节共同上限补测，双方 **3/3**，TEA/Pi **117,126/107,674**，TEA **多 8.78%**。两种配置不拼接比例。
- 中型任务正收益与小型 Unicode/大型重试负收益均保留。大型重试补测中，更多请求导致累计输入高；应调查发现与多余工具循环，尚无因果归因。
- 本轮只比较两套集成配置，不能将整体差异分摊到某个单项优化，也不能证明稳定优势、泛化能力或正式发布门禁。三类自编 JavaScript 样本、每配置一轮；需要父版本消融、重复运行与未见真实项目。
