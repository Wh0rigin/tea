# S2：有界批量读取实验

## 假设

允许模型一次调用读取多个相关文件，可能减少模型往返和重复携带历史的输入 Token。模型原本也能在一条回复中发起多个单文件读取，因此不能用工具调用次数代替真实 Token 收益。

## 候选

- SDK 实验开关 `batchReads: true`，默认关闭；单文件工具保持可用。
- `read_files` 一次接受 1–4 个文件及各自的起止行，每个文件最多返回 2500 字符。截断会提示缩小范围，且不将该范围缓存为完整证据。
- 沿用 UTF-8 检查、路径边界、敏感文件保护、脱敏、源码 SHA-256 和已读证据。某文件失败不吞掉其他文件成功结果；取消信号中止整个调用。
- 每个成功结果保留自己的路径和版本。ContextOS 从持久化结果重建全部依赖；任一依赖变化时保守地停止召回整批旧内容，需要重新读取。这一版不支持在 ContextOS 中单独淘汰同一批内某个文件。
- 批中包含当前活动文件或 AGENTS/README 时，保护整批结果。额外工具定义与 JSON 包装都有 Token 开销；小文件可能收益为负。

## 预先确定的实验

- 基线 `e9ff015`：撤销 S1 后的版本。候选 `7ea8d82`。
- 现有八道自编 Node.js 任务，四个难度，每题每版本三次，共 48 次。
- 同一模型 `glm-5.3-flash`、enabled thinking、low effort、4096 输出上限、32768 上下文容量；每次独立相同初始文件，交替运行顺序。
- 任务 24 次工具调用上限、90 秒请求超时、10 分钟任务超时；每题预留 1 USD，整组上限 8 USD。价格仅用于保守预算核算。
- 所有任务先通过初始/参考实现的公开和隐藏验收控制，再开始付费调用。冻结源码、题目、脚本及配置指纹。
- 未知用量保留预留并停止，不重试，不将未知计为零。
- 综合门槛：覆盖完整、总验收和每题验收不下降、所有尝试的累计 provider Token 降低。独立代码正确性与保护文件/验证流程验收分别记录。
- 成功柱仅包含验收通过的样本；失败用量以叉号显示，仍计入全尝试总量。

## 实验结论：不采用

48/48 次完成，全部用量已知，冻结源码未变。全尝试累计 Token：775,728 → 864,709，**增加 11.47%**；完整验收 20/24 → 21/24，独立代码行为均为 23/24。缓存、并发题的验收分别从 3/3 降至 2/3，未满足逐题不退化门槛。

双方均通过的 18 对子集减少 11.65%，三轮变化方向不一致；成功子集存在筛选效应，不能替代全尝试结果。模型只在 3/24 个候选任务中使用批量读取，共 8 次调用、2 次参数错误；模型请求总数 208 → 216，未减少。首次配对输入平均多约 174 Token。

额外离线检查发现：批量结果交付前取消，会留下未交付的已读缓存；下次读取错误地声称原文仍在历史中。此问题属于冻结候选，未用来解释真实实验的 Token 差异。复现：`node scripts/check-coding-s2-cancellation.mjs`，不调用 API。

候选专项及全量测试最初为 325/325，未覆盖上述取消交付反例。运行时与候选测试已撤销，src/ 与基线 e9ff015 一致。恢复版首跑 319/320（本地模拟网关 fetch bad port），源码和测试不变的专项重跑 14/14、全量重跑 320/320。

[完整报告、逐次数据及 PNG/SVG](../benchmarks/reports/coding-s2-paired-glm-20261015-v1/README.md)。实测脚本来自 7ea8d82，记录的是 Windows CRLF 文件的 SHA-256；其内容与 Git LF blob 一致。本次显式指定 candidate-ref=7ea8d82。发布入口只将默认候选固定到此提交，防止撤销后误测当前 HEAD。
