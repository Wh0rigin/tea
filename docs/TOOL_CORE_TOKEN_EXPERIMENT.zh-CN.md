## 协议（付费前确定）

- 原八道自编 Node.js 编码题，每题两版本各三次，共 **48 次**；每次独立相同初始文件，按题目及轮次交替先后顺序。
- GLM-5.3-flash，enabled thinking / low effort，4096 输出；32768 上下文、4096 预留、256000 字节请求上限，ContextOS、自动压缩与 24 次工具尝试保持一致。
- 每请求 90 秒、命令 120 秒、任务 10 分钟。每次预留 1 USD、整组 8 USD；输入 0.8 / 输出 2.8 USD/MTok 只作既有保守预算参数，非账单证明。
- 所有题目先验证初始公开测试通过/隐藏失败，以及参考实现全部通过；固定题目、引擎和入口指纹，执行前及结束核对。
- 未知用量保留预留并停止，不自动重试、不按零填充。质量失败继续后续独立样本。后台进程隐藏运行，记录 PID 和日志；进程消失后先审计未结算请求，不盲目重启。
- 全尝试累计 provider Token 包含缓存输入及输出中的思考，不重复累加。未知和失败保留；成功柱排除失败，其用量单独显示。
- 验收与独立代码行为分别报告总体及每题，候选任一下降均不满足无退化门槛。只有覆盖/用量完整且全部质量门槛满足、全尝试 Token 减少，才满足本轮数值门槛；这仍不证明因果或统计显著性。
- 报告每轮、每题、双方成功子集、请求数及首次输入差。不同历史实验不合并计算收益，不用成功子集替代总体。

## 已准备的非流式方案（尚未启动付费）

`scripts/compare-tool-core-json.mjs` 使用相同冻结源码、模型、思考等级、任务、次序、预算和验收；两边均设置 `stream=false`，新 run ID 与原流式结果分开。八题初始/参考预检通过，冻结的两个模型适配器在回环服务器上发送相同 JSON 请求并接收完整构造用量；模型适配器专项 **21/21** 通过。回环检查不调用 provider，不测真实 Token。

该方案改变传输方式，不修改生产默认设置。需要用户明确允许新一轮付费对比后执行；原未知用量继续保留，不以新运行覆盖、不混入新组的收益分母。
