# S4：压缩已被后续验证替代的失败输出

## 假设与边界

失败日志在修复后仍随请求重复发送。若同一用户回合中，完全相同的验证命令随后成功，可将旧失败转为 ContextOS 历史引用，降低重复输入；这不代表当前源码一定正确。

实验 SDK 开关 `compactResolvedTests: true` 默认关闭，仅作用于 ContextOS 请求投影：

- 只匹配 `run_tests` / `run_shell` 中的真实验证命令，命令文本必须完全一致。
- 失败必须有明确非零退出码，后续成功必须有 `exit=0` 且没有零测试结果。
- 用户新消息清空匹配范围；不同测试命令、Git 诊断、超时、取消、拒绝及执行器异常不构成解决证据。
- 最近工具回合继续保留，未解决及后来重新失败的输出继续保留；不改变验证状态或保护文件规则。
- 历史引用标记替代它的成功工具调用 ID；保留原工具配对、签名、用户要求、完整规范历史与加密日志，通过现有召回恢复细节。
- 这类失败可在常规 ContextOS 阈值以下尝试投影，但仍执行包含召回工具定义与指导语的整体请求字节收益检查；没有净收益就退回原请求。

## 验证与对比计划

专项覆盖默认关闭、精确匹配、零测试、执行错误、用户边界、近期保护、无收益回退、重新失败、混合批次、实际修复执行、加密日志及恢复。

候选专项 7/7，全量 327/327，无跳过。固定历史的离线投影控制使用冻结的两个引擎：无失败、未解决失败、短已解决失败的请求指纹相同；长已解决失败的请求 15,733 → 5,332 UTF-8 字节。这是序列化字节，不能当作真实 Token 收益。真实实验单列发生替换的任务数、不同失败数及请求投影次数；没有触发的样本不作机制归因。

从 main `6a50dc5` 对比独立冻结的 S4 候选，不包含已撤销的 S1/S2/S3。八道现有自编编码题，每版本三次，共 48 次；相同模型 GLM-5.3-flash、enabled thinking / low effort、4096 输出、32768 上下文、4096 预留、24 工具尝试、256000 字节请求上限。每请求 90 秒，每任务 10 分钟，单次预留 1 USD、整组 8 USD，价格沿用输入 0.8 / 输出 2.8 USD/MTok 作为保守预算，非账单证明。

工具执行沿用两个冻结版本相同的 120 秒命令超时；验收执行器单次 15 秒。任务内模型自行重复命令也消耗原任务时间，不重置 10 分钟上限。任务失败后继续其余独立样本；只有未知计费、预算或实验执行器错误会中止整组。

冻结任务、源码、入口和模型配置后执行；未知用量停止并保留预留，不付费重试。保留所有失败成本，柱形图仅用成功样本。门槛为完整覆盖和已知用量、总验收与逐题验收不下降、全尝试累计 provider Token 降低。双方通过子集及实际触发次数单列，不替代全量结论。每题三次属于小样本。

本阶段完成后停下等待审核；无收益或质量门槛下降则撤销运行时改动，保留实验记录。

## 代价与限制

本轮只改变请求中的工作集，完整历史仍在内存及加密日志中；不声称单独降低内存或磁盘用量。资格识别增加一次历史扫描。替换旧消息也可能改变服务端缓存命中；累计 Token（含缓存输入）与实际账单、延迟并非同一指标。全组轨迹差异尤其是未触发的任务，不足以单独证明机制的因果收益。

收益窗口只包括同一命令通过后的后续模型请求。一次通过的任务没有旧失败可替换；修复通过后马上结束的流程，也只有很短的收益窗口。不能为了提高触发次数而减少未解决失败的保护。
