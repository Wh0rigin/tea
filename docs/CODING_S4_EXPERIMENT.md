# S4：压缩已被后续验证替代的失败输出

## 假设与边界

失败日志在修复后仍随请求重复发送。若同一用户回合中，完全相同的验证命令随后成功，可将旧失败转为 ContextOS 历史引用，降低重复输入；这不代表当前源码一定正确。

实验 SDK 开关 `compactResolvedTests: true` 默认关闭，仅作用于 ContextOS 请求投影：

- 只匹配 `run_tests` / `run_shell` 中的真实验证命令，命令文本必须完全一致。
- 失败必须有明确非零退出码，后续成功必须有 `exit=0` 且没有零测试结果。
- 用户新消息清空匹配范围；不同测试命令、Git 诊断、超时、取消、拒绝及执行器异常不构成解决证据。
- 最近工具回合继续保留，未解决及后来重新失败的输出继续保留；不改变验证状态或保护文件规则。
- 历史引用标记替代它的成功工具调用 ID；保留原工具配对、签名、用户要求、完整规范历史与加密日志，通过现有召回恢复细节。
- 这类失败可在常规 ContextOS 阈值以下尝试投影，但仍执行包含召回工具定义与指导语的整体请求字节收益检查；没有净收益就退回原请求。
