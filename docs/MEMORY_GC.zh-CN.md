# ContextOS 垃圾回收与默认自动压缩

[English](MEMORY_GC.md)

## 默认行为

自动压缩现在默认开启。每次请求前，完整请求达到配置字节保护的 80%，或常驻历史序列化大小达到 4 MiB，才尝试摘要；不是每隔固定轮数执行。每个任务仍最多自动尝试两次，摘要使用原模型、思考等级和费用预算。

默认 `memory-gc=auto`。自动模式创建本地加密会话；CLI 默认开启 ContextOS，可通过显式记忆/历史选项覆盖。压缩与垃圾回收承担不同职责：摘要缩短模型输入，GC 释放不再需要常驻的正文和缓存。两者均可显式关闭。

```sh
tea --interactive --memory-policy contextos --session work --max-cost-usd 1
tea --interactive --resume work --memory-policy contextos --max-cost-usd 1
tea --interactive --compaction off --memory-gc off --max-cost-usd 1
```

## 先提交，再释放

1. 摘要格式完整、用量已经结算，且候选请求比旧请求更小，才接受检查点。比较时计入原文要求和未来历史恢复入口的开销。
2. 旧工具证据与模型笔记写入认证加密载荷，引用目录留在磁盘；原始历史也保留在日志与检查点引用的载荷中。
3. 单独提交 `memory_gc_checkpoint`：记录保留的后缀、用户原文、项目规则引用、摘要和当时真实验证状态。
4. 提交成功后才从 `session.messages` 移除已覆盖前缀；清理旧索引、读取缓存和不再使用的源码快照。原有数组就地裁剪，避免运行循环仍持有旧正文数组。
5. 只保留近期消息、原文要求、运行状态和受容量限制的冷证据缓存。ContextOS 按需从磁盘恢复原文，检查版本后分页返回。

检查点提交失败，不释放旧消息。已提交检查点之后即使进程立即中断，仍能恢复当时的待验证修改；不依赖尚未写入的下一条运行状态。

## 内存中的保护根

- 用户要求按原文保留；摘要不能重新解释用户约束。
- 近期完整工具批次及其思考/签名保持完整。
- 已观测的项目规则保留引用，装配请求时按需取出并检查版本，重新锚定有效规则。
- 待验证修改、失败观测来源和费用责任由运行状态/持久化事实保留；历史测试结果不认证当前代码。
- 冷证据依旧可搜索，摘要后不会因没有新的回收动作而丢失 `search_history` 入口。

冷热转换并未抹掉旧失败或源码：它们转入磁盘历史，可按需恢复。源码手动修改仍会使旧引用、搜索预览及恢复副本失效。

## 有界缓存与资源保护

- `TEA_MEMORY_CACHE_BYTES`：默认 262,144 字节。冷正文使用 LRU；单条超过缓存容量时只临时读取，不留在缓存。元数据缓存最多 128 项。
- `TEA_MEMORY_MAX_RESIDENT_BYTES`：默认 4,194,304 字节。统计当前历史与保留用户原文的序列化大小；达到阈值触发自动压缩。
- `TEA_SESSION_MAX_STORAGE_BYTES`：默认 536,870,912 字节，限制单会话日志和载荷。到达限制停止写入，要求显式提高容量或归档/删除该会话，不擅自删完整历史。
- `--memory-gc auto|off` / `TEA_MEMORY_GC`：默认 `auto`。
- `--compaction auto|off` / `TEA_COMPACTION`：默认 `auto`。

摘要无效、无法缩小请求、预算不足或保留内容依旧过大时，不循环调用模型。若常驻历史依旧达到限制，任务以 `memory_limit_reached` 结束。用户可显式调整容量或开始新会话。

这里有界的是冷正文缓存；4 MiB 指序列化历史阈值，**不是 Node.js 堆或 RSS 的硬上限**。日志事件元数据、用户约束、任务状态与临时反序列化仍占内存。极长历史的恢复、搜索和磁盘 GC 耗时会增长；当前没有宣称整个进程内存恒定。

## 磁盘 GC：只清孤儿，完整历史保留

成功内存回收后执行本地 mark-and-sweep：从所有已提交日志行标记载荷，再标记归档目录和检查点中的嵌套载荷引用。只删除未被任何这些根引用、且至少 24 小时前创建的载荷；每次最多扫描 1,000 个目录项。

收集期间持有会话单写者锁，目标必须是本会话真实载荷目录中的常规哈希文件；不删除密钥、日志、兄弟会话、未知名字或链接。损坏的已提交根会中止检查，不会猜测后删除。

**没有自动 TTL 删除已提交历史，也没有自动删除整个旧会话。** 旧记录可能用于恢复和核查未知计费，不能仅因模型摘要没提到就销毁。磁盘空间实际能回收多少取决于是否存在中断写入产生的孤儿，不保证磁盘总量下降。

手动清理整个会话：

```sh
tea sessions list
tea sessions delete work
```

## 恢复、回退与计费

恢复按事件逐个解密，不同时载入全量正文；最新 GC 检查点选择当前后缀，冷证据按需读取。启动时校验嵌套载荷完整性。工作区、模型、端点身份和未知计费约束沿用原机制；`/new` 清空活跃引用与缓存，但保留修改义务、费用和磁盘历史。

需要原始完整历史模式时，可以显式恢复：

```sh
tea --interactive --resume work --memory-policy full-history --compaction off --memory-gc off --max-cost-usd 1
```

这会重新加载原始消息，故可能占用较多内存。日志是加密载荷配合 JSONL 元数据；密钥仍在本机，不保护能够同时读取密钥和密文的本机用户。

## 当前验证与未完成的证明

新增专项覆盖：持久化提交失败、检查点之后中断、跨进程冷召回、手动源码变更、规则过期、UTF-8 原文、缓存容量、磁盘孤儿、嵌套损坏、未知计费、重置、自动触发与容量停止。

脚本压力检查提供 12/36/72 个工具轮次，各重复三次，GC off/auto 共 18 次；每次使用一次固定脚本摘要，零供应商调用。它测量**常驻历史序列化字节**，不测真实堆、RSS 或 Token。真实性能与 Token 的发布结论需要另做固定模型的付费对照，不能由本地字节减少推导。
## 真实 Token 验证

[TEA 专项报告](../benchmarks/reports/contextos-gc-tokens-20261014/README.zh-CN.md)：72 次全部通过。正常任务相较直接父版本 Token **增加 6.54%**，没有触发压缩；同一新版的超阈值压力消融实验，包含摘要后**减少 45.81%**；未达到阈值的压力组**增加 5.10%**。正常任务优化门槛未通过，不能宣称普遍节省或单独归因于 GC。
