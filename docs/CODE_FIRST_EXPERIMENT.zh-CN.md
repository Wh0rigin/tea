# 代码优先检索：强制路由实验

日期：2026-10-17。**筛选失败，本轮运行时及专项测试已撤销，当前不提供 codeFirst 开关。** 下文描述冻结候选 `ed9ea6a` 的 SDK `codeFirst:true` / 环境 `TEA_CODE_FIRST=1` 实验。此轮替换模型的检索动作入口，不额外调用模型生成计划；编辑和验证仍使用原工具。保留冻结实现及证据，待用户审核，不自动下一阶段或合并。

## 与上一版的区别

可选版只有新增工具，真实采用 0/6。本版在模型定义中移除 list_files/search_code；read_file 仅允许读取 AGENTS.md / AGENTS.override.md；源码读取必须使用 retrieve_code 的 read/readHit。ContextOS standalone recall_context/search_history 也隐藏并拒绝，改为编排内 history/recall。工作区指令仍走独立普通 read_file，保留规则保护与版本身份。

未声明的原子检索调用会在 ToolService 层拒绝，不能只靠修改提示。run_tests/run_shell 仅允许实际白名单验证，无任意命令批准或 Git 诊断回退。编排内部临时执行器保留原读取/搜索/路径/脱敏保护。能力声明、模型模式说明与实际限制一致。新建空目录任务不强行执行无意义检索。

这是模型工具入口约束，不是操作系统级文件隔离：SDK 直接调用 WorkspaceTools 方法、验证程序及模型新写的测试本身仍有 Node 文件能力，不能声称阻止所有恶意绕过。测试保留相同非交互批准条件，审计实际工具路线。

沿用上一版受限语法、8 子操作/4 页/10KB、求值/时间边界；不执行任意 JS，不支持完整方法调用和任意文本处理。emit 页在外层交付后才更新证据；部分失败/取消不污染读缓存；文件变化和缺少元数据令旧引用失效。一个编排结果仍为一个保守版本依赖的 ContextOS 单元，而非独立子页索引。未新增 plan/working 任务状态机。

- 相同模型 GLM-5.3-flash、enabled thinking / low、4096 输出、流式、上下文/压缩、初始文件及验收。按题和轮次交替先后，每次独立初始化。基线为本轮前正常工具版本，候选为代码优先完整模式；比较包含模式提示、能力声明、定义替换与执行策略的整体变化，不把总差额全部归因于解释器。
- 固定三个任务均先通过初始公开通过/隐藏失败及参考实现全通过控制。冻结源码、任务依赖及入口指纹。默认关闭模式的原有工具定义保持相同；编辑工具 schema/语义不变。候选权限收窄和检索定义变化明确记录。

- 记录编排调用/错误、子操作、路由拒绝、源码任务采用率、首次输入开销、请求数、provider Token、完整验收及独立代码行为。强制入口的采用本身不是收益指标，短任务允许不检索。
- 只有覆盖/用量完整、总体和逐题质量不下降且全尝试 Token 更低，才通过数值筛选；还需实际执行成功的编排作为机制证据。不泛化到生产/其他模型，不混入上一轮独立数据。未通过撤销运行时，冻结实现及报告保留；通过也等待审核。

## 实际结果

入口冻结 `6e31bce`，运行 `code-first-screen-glm-20261017-v1`，12/12 完整结束，全部用量已确认。双方完整验收及独立代码行为均 **6/6**，没有未知用量、付费重试或因质量失败提前截断。

- 总 provider Token **165,794 → 214,244，增加 29.22%**；请求 **49 → 63**，增加 28.57%。缓存输入及输出中的思考已包含，不重复累加。
- 短任务 **20,920 → 26,831（+28.26%）**；重试策略 **47,195 → 65,055（+37.84%）**；分页 **97,679 → 122,358（+25.27%）**。每题只有两轮，是此题组的筛选结果，不是通用因果结论。
- 逐轮 **74,826 → 120,189（+60.62%）**、**90,968 → 94,055（+3.39%）**；两轮均增加。
- 同题首次输入差平均 **+28 provider Token**，不支持把总增加主要解释为首次固定输入。后续输入还受历史、ContextOS、错误和生成路径影响。
- 候选采用 **6/6**，执行 **34** 次编排，其中 **21 成功、13 失败**（成功率 **61.76%**）；实际启动 **39** 个子操作，成功 **38**。两者分母不同，失败程序可能在执行前就被拒绝，或执行多个子操作后整体失败。
- 多子操作程序 **8** 次，其中整体成功 **6** 次。没有单独原子入口的路由拒绝；模型遵循了强制入口。采用和组合执行已发生，但没有稳定减少请求数。

## 已定位的代价

13 次程序失败中，**8 次不支持的语法、2 次语法/接口解析错误、2 次四页输出上限、1 次把工作区指令放入编排读取**。这不是 13 次编码任务失败；最终都修复并通过。错误费用保留在任务总量，不能将所有后续费用都宣称可避免。

加密事件显示，模型生成了普通 JS 字符串拼接、`.slice()`、无花括号 for 等当前解释器不支持的写法；一段含 `+` 的相同程序还重复提交。只有整段语法检查通过才执行，因此被语法检查拒绝的程序没有进行前部读取或交付。随后模型多次退回单操作读取。分页第二轮又两次触及四页上限，已执行的临时读取因整段失败不计入已交付证据，这是安全但昂贵的行为。

普通实现/新增测试的验证失败同样贡献了往返差异；不能把全部 29.22% 都归因于解释器。基线和候选是独立生成轨迹、只做两轮，不能用本结果否定所有 Code Agent 实现。与上一版 +70.46% 是不同基线批次，不能相减作为本版优化收益。
