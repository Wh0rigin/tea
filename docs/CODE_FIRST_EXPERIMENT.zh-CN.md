# 代码优先检索：强制路由实验

日期：2026-10-17。实验性 SDK `codeFirst:true` / 环境 `TEA_CODE_FIRST=1`，默认关闭。此轮替换模型的检索动作入口，不额外调用模型生成计划；编辑和验证仍使用原工具。结果出来后决定是否撤销，待用户审核，不自动合并或扩大实验。

## 与上一版的区别

可选版只有新增工具，真实采用 0/6。本版在模型定义中移除 list_files/search_code；read_file 仅允许读取 AGENTS.md / AGENTS.override.md；源码读取必须使用 retrieve_code 的 read/readHit。ContextOS standalone recall_context/search_history 也隐藏并拒绝，改为编排内 history/recall。工作区指令仍走独立普通 read_file，保留规则保护与版本身份。

未声明的原子检索调用会在 ToolService 层拒绝，不能只靠修改提示。run_tests/run_shell 仅允许实际白名单验证，无任意命令批准或 Git 诊断回退。编排内部临时执行器保留原读取/搜索/路径/脱敏保护。能力声明、模型模式说明与实际限制一致。新建空目录任务不强行执行无意义检索。

这是模型工具入口约束，不是操作系统级文件隔离：SDK 直接调用 WorkspaceTools 方法、验证程序及模型新写的测试本身仍有 Node 文件能力，不能声称阻止所有恶意绕过。测试保留相同非交互批准条件，审计实际工具路线。

沿用上一版受限语法、8 子操作/4 页/10KB、求值/时间边界；不执行任意 JS，不支持完整方法调用和任意文本处理。emit 页在外层交付后才更新证据；部分失败/取消不污染读缓存；文件变化和缺少元数据令旧引用失效。一个编排结果仍为一个保守版本依赖的 ContextOS 单元，而非独立子页索引。未新增 plan/working 任务状态机。
