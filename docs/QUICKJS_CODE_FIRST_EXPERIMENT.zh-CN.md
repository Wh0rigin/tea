# QuickJS Code Agent 实验（2026-10-17）

## 假设与范围

此前强制 Code Agent 的 12 次测量中，正确率没有下降，但 Token 增加 29.22%。34 段检索程序中有 13 次错误，主要来自自定义 JavaScript 子集的语法限制。此次尝试改用 QuickJS/WASM，并在明确的检索配额耗尽时保留已经 emit 的结果，检验能否减少修复轮次。

这不是已证实的 Token 优化。默认模式仍关闭 `codeFirst` 和 `retrievalCode`。

## 实现

- 固定依赖 quickjs-emscripten 0.32.0，通过锁文件固定传递依赖；不使用 Node eval、Function 或 vm 执行检索程序。
- 每段程序创建独立 QuickJS runtime，16 MiB guest heap、256 KiB stack、15 秒墙钟检查和中断次数限制；最多 8 个待完成宿主调用。
- 宿主只暴露现有只读检索 API。没有宿主进程、模块加载器、文件写入或 shell。
- JSON 参数隔离；真实证据页通过宿主签发的随机 ID 和 guest WeakMap 关联，不允许字符串拼接冒充原始证据页。
- 8 次操作、4 页、10 KB 输出边界；只有配额限制且已 emit 时才返回标记 incomplete 的前缀。语法、宿主错误、越界和取消不提交暂存证据。
- 只有外层 tool_result 持久化后，实际输出的页才计入已呈现证据；未输出、被拒绝的页不计入。
- CPU 中断不是宿主 I/O 的硬终止：已经启动的只读操作会等待结算，再释放 VM，避免异步回调访问已释放句柄。

## 离线验证

- 34 段原始程序全部回放，旧解析器通过 24/34，新执行器在模拟 API 下通过 33/34。
- 剩余 1 段将 opaque page 拼接为字符串，保持拒绝并提示直接 emit。模拟回放不验证真实文件结果，也不等于任务成功率或 Token 收益。
- 完整确定性测试：360/360 通过。包括标准语法、CPU/内存限额、并发上限、取消、伪造页、缓存污染和部分页交付。

## 真实流式测量协议

- 3 个已使用的自编 Node 任务：短任务、依赖检索修复、分页修复；各 1 对，合计 6 次，属于小规模筛查。
- 正常工具模式作为 baseline；QuickJS 强制 Code Agent 作为 candidate。固定相同任务、初始文件、GLM-5.3-flash、enabled thinking、low effort、4096 输出上限及 ContextOS 设置。
- 每任务 1 USD 预留，总控制上限 2 USD；输入/输出控制估价 0.8/2.8 USD 每百万 Token，不代表最终账单。
- 请求 90 秒、任务 600 秒、24 次工具额度（包括子检索）；全部流式，未知用量保留预留并停止，不自动重试。
- 同时冻结源码、任务、runner、transport observer 和 npm 依赖内容指纹。所有尝试均纳入总 Token；失败不能按零处理。
- 门槛：用量完整、每类验收不下降，全部尝试累计 provider Token 下降。样本不能支持生产泛化结论。
