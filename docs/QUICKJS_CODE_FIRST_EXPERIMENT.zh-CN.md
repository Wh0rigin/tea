# QuickJS Code Agent 实验（2026-10-17）

## 假设与范围

此前强制 Code Agent 的 12 次测量中，正确率没有下降，但 Token 增加 29.22%。34 段检索程序中有 13 次错误，主要来自自定义 JavaScript 子集的语法限制。此次尝试改用 QuickJS/WASM，并在明确的检索配额耗尽时保留已经 emit 的结果，检验能否减少修复轮次。

这不是已证实的 Token 优化。默认模式仍关闭 `codeFirst` 和 `retrievalCode`。

## 实现

- 固定依赖 quickjs-emscripten 0.32.0，通过锁文件固定传递依赖；不使用 Node eval、Function 或 vm 执行检索程序。
- 每段程序创建独立 QuickJS runtime，16 MiB guest heap、256 KiB stack、15 秒墙钟检查和中断次数限制；最多 8 个待完成宿主调用。
- 宿主只暴露现有只读检索 API。没有宿主进程、模块加载器、文件写入或 shell。
- JSON 参数隔离；真实证据页通过宿主签发的随机 ID 和 guest WeakMap 关联，不允许字符串拼接冒充原始证据页。
- 8 次操作、4 页、10 KB 输出边界；只有配额限制且已 emit 时才返回标记 incomplete 的前缀。语法、宿主错误、越界和取消不提交暂存证据。
- 只有外层 tool_result 持久化后，实际输出的页才计入已呈现证据；未输出、被拒绝的页不计入。
- CPU 中断不是宿主 I/O 的硬终止：已经启动的只读操作会等待结算，再释放 VM，避免异步回调访问已释放句柄。

## 离线验证

- 34 段原始程序全部回放，旧解析器通过 24/34，新执行器在模拟 API 下通过 33/34。
- 剩余 1 段将 opaque page 拼接为字符串，保持拒绝并提示直接 emit。模拟回放不验证真实文件结果，也不等于任务成功率或 Token 收益。
- 完整确定性测试：360/360 通过。包括标准语法、CPU/内存限额、并发上限、取消、伪造页、缓存污染和部分页交付。

## 真实流式测量协议

- 3 个已使用的自编 Node 任务：短任务、依赖检索修复、分页修复；各 1 对，合计 6 次，属于小规模筛查。
- 正常工具模式作为 baseline；QuickJS 强制 Code Agent 作为 candidate。固定相同任务、初始文件、GLM-5.3-flash、enabled thinking、low effort、4096 输出上限及 ContextOS 设置。
- 每任务 1 USD 预留，总控制上限 2 USD；输入/输出控制估价 0.8/2.8 USD 每百万 Token，不代表最终账单。
- 请求 90 秒、任务 600 秒、24 次工具额度（包括子检索）；全部流式，未知用量保留预留并停止，不自动重试。
- 同时冻结源码、任务、runner、transport observer 和 npm 依赖内容指纹。所有尝试均纳入总 Token；失败不能按零处理。
- 门槛：用量完整、每类验收不下降，全部尝试累计 provider Token 下降。样本不能支持生产泛化结论。

## 实测结果与决定

运行 `quickjs-code-first-screen-glm-20261017-v1`，冻结候选 `9c2eea6`、基线 `dd19de3`、runner `dd623d3`。6/6 次完成，全部用量已知；源码、任务、runner、observer、npm 依赖指纹均未改变。没有流式截断、未知用量或自动付费重试。

- 全尝试 provider Token：91,008 → 82,349，表面减少 **9.51%**。
- 完整验收与独立代码行为均由 **3/3 → 1/3**；因此不构成有效优化。失败成本包含在总量，不能把失败提前停止的低用量当成收益。
- 模型请求：26 → 33，增加 **26.92%**。
- 短任务：9,830 → 11,638，**增加 18.39%**，两边通过。
- 依赖检索修复：23,398 → 49,217，**增加 110.35%**，候选工具额度耗尽，代码行为未通过。
- 分页修复：57,780 → 21,494，**减少 62.80%**，候选失败，不能宣称省 Token。
- 候选 3/3 采用编排，25 段程序、6 次工具错误、42 次已开始的子操作、41 次成功结算。8 段多操作程序中 7 段未报工具错误，但这些数字不代表有用证据或任务成功。
- 加密事件审计发现 **15 次空对象输出**，21/25 段程序没有 await 关键字（描述性文本检查，非语法分析）。没有真实调用触发 incomplete 前缀，不能宣称部分交付带来了线上收益。

### 根因

QuickJS 解决了原有语法子集限制，却引入了实际使用上的异步契约问题：`read/search/list` 返回 Promise，模型多次写成 `emit(read(...))` 或直接访问 `search(...).items`。Promise 序列化成为 `{}`，没有报错，却也没有把读取内容呈现给模型。于是模型重复读取、访问不存在的字段，甚至探测不存在的文件，消耗了调用额度。

这属于候选接口缺陷，不能只归因于模型“不遵循说明”。现有回放集覆盖以前的程序，未覆盖新轨迹中漏 await 的错误用法；测试通过不能代替真实端到端质量。全组涨跌也不能全部归因于执行器，普通编辑和测试修复同样贡献用量。

### 撤销与下一步建议

按预先声明的门槛，撤销本次 src/tests、package.json 和 package-lock.json 的运行时变动，恢复至 dd19de3；不默认开启、不合并。冻结实现和依赖锁仍保留在 9c2eea6，测量入口保留在 dd623d3，报告与失败证据继续保留。

下一步应先离线统一同步/异步契约：评估 Asyncify 使宿主异步检索在 guest 中表现为同步结果，兼容有/无 await；或严格拒绝 Promise 及嵌套 Promise 的 emit/序列化，并提供明确错误。前者需要验证并发和重入限制，后者仍有额外修复轮次的代价。两种设计都应补充错误用法回归，并用未参与调试的任务复验。当前不启动下一轮付费测试，等待审核。

## 复现与限制

先在独立目录检出 runner 提交 dd623d3（包含冻结候选及其依赖锁）并运行 `npm ci --ignore-scripts`，再使用冻结 runner 与锁定源码、任务。回滚后的正常运行时不需要 QuickJS；不要在缺失依赖时直接重跑候选引擎。

34 段原始程序来自私有加密会话，公开报告只导出聚合计数；该回放无法仅凭公开报告完整复现。此处只有三道反复使用的自编题、每题一对，不能估计生产任务的平均节省率。部分交付只有确定性测试覆盖，线上未触发。QuickJS 限制作用于检索 guest，不是对项目测试或整个操作系统的沙箱。
