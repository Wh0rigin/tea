# S3：精简标准工具说明

## 假设与范围

工具定义随每次模型请求发送。缩短重复的描述文字可以减少固定输入，但只有真实配对测量能判断是否被更多错误或往返抵消。

从合并 PR #7 后的 main `6a50dc5` 开始，仅修改七个标准工具的 description。保留原参数结构、系统提示、能力通知、错误反馈、执行器、权限和验证条件。ContextOS 召回及词表学习工具保持原说明。实验由 SDK `compactToolDescriptions: true` 开启，默认关闭。

能力通知原本就只在首次或能力变化时追加，不重复实现该机制。追加一次的内容仍会随历史再次提交；系统和工具定义也不能假定服务端自动记住。本轮不删除后续请求中的必要规则。

## 离线验证

- 专项 4/4；全量 324/324，无跳过。
- 大小目录、文件创建开关、游标、动态记忆工具均检查参数结构完全一致。
- 会话内开关切换不修改旧消息，不改变系统和能力版本，不重复声明能力，不污染共享定义。
- 小目录工具定义 2717 → 2421 UTF-8 字节（减少 10.89%）；大目录 2953 → 2613（减少 11.51%）。这是工具定义字节，**不是整个请求或 provider Token 收益**。

## 冻结实验

- 八道现有自编 Node.js 编码题，四个作者分级，每题每版本三次，共 48 次。每次新工作区，同题交替先运行两个版本。
- GLM-5.3-flash、enabled thinking、low effort、4096 输出、32768 上下文、4096 预留、256000 字节请求上限、24 次工具尝试。
- 请求 90 秒、任务 10 分钟；每次预留 1 USD，整组 8 USD，核算价格沿用输入 0.8/输出 2.8 USD/MTok，仅用于预算，不是账单证明。
- 先完成八题初始/参考实现验收控制及两种目录工具参数指纹一致性检查，再开始付费调用。
- 用量未知就停止并保留预留，不自动付费重试；保留所有失败成本。柱形图只使用成功样本，失败成本单独显示。
- 采用门槛：用量与覆盖完整、总验收及每题验收不下降、所有尝试累计 provider Token 更低。代码行为、保护文件及流程验收分别记录。
- 首次请求输入单列，用来检查固定开销是否确实减少；不能把固定字节或成功子集改进替代全尝试 Token 结果。

## 实际结果与处置

基线 `6a50dc5b131678fbc2d41cf181414f7896c70b50`，候选 `7740845fffb4a8685d193c903c9dc5e9582be2a6`；实验入口冻结于 `de4f01a`。48 次全部完成，用量均已知，没有付费重试。

- 全尝试累计 provider Token：594,355 → 761,024，**增加 28.04%**；三轮分别增加 28.43%、36.63%、18.28%。
- 完整验收：20/24 → 18/24（83.33% → 75.00%，下降 8.33 个百分点）。独立代码行为通过 20/24 → 22/24；候选额外存在四次修改保护测试文件的违规，不能把完整验收下降都解释为代码错误。
- 区间题完整验收 3/3 → 1/3，依赖图题 3/3 → 2/3，未通过预先设置的逐题质量门槛。
- 首次请求输入平均减少 41.21 Token，但请求数 180 → 203、输出 Token 45,954 → 52,705。CSV 题候选多消耗 160,304 Token，约占总增量 96.18%；双方均通过的 17 对累计 Token 反而增加 0.03%，也没有获得整体收益。

因此本次方案不采用。缩短说明带来小幅固定节省是实测现象，但不能证明它必然导致某种修复行为；模型轨迹具有波动，每题三次不足以证明生产环境的因果关系或统计显著性。

候选运行时修改及四个专用测试已撤销，`src/` 与基线一致。候选专项 4/4、全量 324/324；撤销后全量 **320/320**，首次执行通过，无跳过。保留候选提交、冻结入口、分析脚本与[完整报告及图表](../benchmarks/reports/coding-s3-paired-glm-20261015-v1/README.md)，不修改历史样本或验收标准。
