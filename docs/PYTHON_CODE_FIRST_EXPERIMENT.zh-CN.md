# 同步 Python Code Agent 实验（2026-10-17）

## 假设

上一轮 QuickJS 测量出现 15 次空对象输出，源于检索函数返回 Promise、模型漏写 await。本轮采用同步 Python 工具接口，验证消除异步契约错误后，能否减少检索修复轮次，并在验收不下降时减少累计 provider Token。比较正常工具模式与完整 Python code-first 模式，不是单独切换语言的消融实验。

## 实现与边界

- Node.js 主循环、源码工具、精确编辑、验证、计量和 ContextOS 保持原有后端；Python 只通过逐条 JSON RPC 编排现有只读检索。
- 独立 CPython 子进程；固定 RestrictedPython 8.5、依赖 wheel SHA-256；使用成熟受限编译器，不自制 Python 语法解释器。
- 工具同步返回字典或宿主签发的不透明证据页。支持关键词参数/字典参数、普通循环、切片、函数、推导式、emit/print；不用 await。
- 不继承 API 凭据；只传递启动所需的系统路径环境变量。禁止导入、宿主文件/进程 API 和反射入口；RPC 不暴露任意宿主方法。
- 限额：每程序最多 8 次子操作、4 页、10 KB 结果；15 秒墙钟、30000 个 Python trace 事件、10 秒 CPU、256 MiB 地址空间/提交内存。Linux 使用 rlimit，Windows 使用 Job Object；建立资源限制失败则不执行程序。
- 只有配额耗尽且已有 emit/print 才交付标记 incomplete 的前缀；语法、非法路径、取消和其他执行错误不提交暂存证据。
- 页只能直接输出；不得拼接、嵌套、伪造或读取 page.text。tool_result 持久化后才将已输出的范围计入证据。复用 SHA-256 版本校验及过期失效。
- RestrictedPython 是语言限制机制，并非操作系统权限沙箱。进程资源限制也不等于权限隔离；本原型默认关闭，不把它作为对恶意代码的生产安全边界。

## 离线门槛

31/31 专项通过：真实同步返回、上一轮错误调用模式的 Python 对应操作、字段错误、页序列化/伪造、部分交付、计数、取消、超时、CPU/内存、非法路径、导入与反射、ContextOS 过期及历史召回、真实编辑后验证。完整回归首版 364/364；UTF-8 修正及完整同步调用策略回归后 **365/365 通过**。

本轮不把旧 JavaScript 程序翻译成 Python 后声称“原样回放成功”；使用明确的 Python 对应回归验证接口契约。

## 依赖与复现

复现时先在独立目录检出 runner 提交 9142744（包含冻结候选及 requirements）；当前撤销后的运行时没有这些实验依赖文件。Python 3.10+，本次实测 CPython 3.13.9，解释器二进制指纹见结果 JSON：

```sh
python -m pip install --require-hashes --no-deps --target .tea/python-runtime -r requirements-python-retrieval.txt
npm test
```

实验模式通过 TEA_CODE_FIRST=1 开启；普通模式无需 Python 依赖。可用 TEA_PYTHON_EXECUTABLE / TEA_PYTHON_DEPS 指定解释器与依赖目录，不固定用户账户路径。CI 候选分支安装同一哈希固定的测试依赖。

## v2 实测结果

冻结候选 **b08e3b7**、runner **9142744**、正常基线 **b6f9395**。运行 `python-code-first-screen-glm-20261017-v2`，12/12 次完成；源码、任务、runner、observer、Python 二进制/版本和依赖内容指纹保持不变。

- 全尝试 provider Token：**141,182 → 183,183，增加 29.75%**。缓存输入及思考输出均计入，失败样本成本没有剔除。
- 完整验收：**6/6 → 5/6**，通过率下降 16.67 个百分点；独立代码行为：**6/6 → 6/6**。
- 候选分页第二轮通过公共、新增和隐藏行为测试，但修改 `tests/public.test.mjs`，违反 AGENTS 明确规定的既有测试保护规则。不是未知用量、超时或隐藏测试误判；因此只把它记为代码行为通过，完整验收失败。
- 模型请求：**44 → 54，增加 22.73%**；首次输入配对均值只增加 **11.67 provider Token**。这不足以支持“主要来自固定提示词长度”的解释。
- 两轮分别增加 **34.38% / 24.57%**；不是单轮偶然下降后选取的结果。
- 短任务合计：20,465 → 22,725，**增加 11.04%**，两边 2/2 验收通过。
- 依赖检索修复合计：40,654 → 45,236，**增加 11.27%**，两边 2/2 验收通过。首轮虽减少 14.91%，第二轮测试修复使两轮合计转为增加。
- 分页修复合计：80,063 → 115,222，**增加 43.91%**；基线 2/2、候选 1/2 完整验收通过。第一轮精确变化为 +57.17%。
- 作为补充，保留同题同轮两边均通过的五对，累计 106,481 → 139,258，仍 **增加 30.78%**；这是事后子集，不替代全样本门槛。

### 机制审计

候选 6/6 使用 Python 编排，19 段程序中 16 段无工具错误，**16 段都实际输出了证据页，共 26 个证据页头**。7 段多操作程序全部无工具错误；27 个已开始的子操作全部成功结算。没有空对象输出，没有 Promise/await 错误，也没有真实触发 incomplete 前缀；部分交付仍只有确定性测试证据。

三次程序错误分别是禁止导入、禁止 open、混合位置与关键字参数被接口拒绝；另有一次通过 run_shell 走未允许调试命令的路由拒绝。普通文件写入/补丁和测试修复同样贡献了往返，不能把 42,001 个额外 Token 全归到这三次错误。

正常工具基线本来就支持同一个 assistant 响应携带多个 tool_use：六次基线共 9 个多原子检索响应。因此“在一段代码里调用多次工具”不自动等于减少模型轮次。真正可能减少轮次的是依赖上一步结果的本地分支、循环和检索；本轮局部收益没有覆盖其他修复开销。该轮也不是 Python 与 JavaScript 的单变量对照，不能据此断言某种语言天生更省 Token。

### 成本、审计与决定

全部用量已知，零命令超时、零流式截断，没有自动付费重试。主对照的控制估价为 0.299912 USD；加上 v1 中止前已知的 0.0097456 USD，共 0.3096576 USD。两次共 13 个已发生的尝试、334,012 provider Token，全部保留；未配对 v1 样本不混入主对照百分比。估价不是发票。

数值和质量门槛均未通过，**撤销本轮 src/tests、CI 安装步骤与 Python requirements 的运行时变动，恢复 b6f9395**。不保留默认开启或默认关闭的 Python 运行时入口；冻结实现 b08e3b7、初版 61b0992 和两版 runner、审计脚本与报告继续留在 Git 历史中。撤销后完整测试 **334/334 通过**，src/tests/CI 与 b6f9395 一致。

## 下一阶段建议（未执行）

1. 先修正符合 Python 惯例的函数签名，覆盖位置参数与关键字参数的组合；提供一致的字典键和显式返回类型。它能减少接口修复，但目前没有测得 Token 收益。
2. 将“只读检索编排”和“通用 Python 执行/调试”的能力界限明确设计；必要的文本处理或标准库能力需要单独评估权限与证据语义。不能只靠增加提示词约束解决接口落差。
3. 用真正需要依赖检索、分支与结果过滤的新任务，先做离线契约检查，再做小规模对照；保留正常工具模式作为基线。当前反复使用的三题不能证明生产泛化。
