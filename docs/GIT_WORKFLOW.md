# Git 流程

Git 仅在本项目目录初始化；用户身份是项目本地配置，不能更改全局配置。`baseline-v0` 是唯一无父版本豁免提交。它必须先通过确定性 Unit 与受控 Replay 自测，再初始化快照及 `v1`–`v3` 分支。

每个优化提交都需保存与直接父提交配对的实际 Live 数据和完整回归证据；不符合准入门槛则保持未提交。版本结束后冻结该版本分支并打 `release-vN`。`main` 只能通过 `--ff-only` 前进到通过完整 Benchmark 的提交。V3 后从新 `main` 建 `v4`、`v5`，不更新已冻结旧分支。所有操作均为本地操作，未经明确要求不推送。

## 当前用户授权（2026-10-11）

用户明确要求认可当前离线改善、把优化百分比写入 commit，并进入下一阶段。按该授权，V1 可提交为离线实验检查点；提交说明必须写明指标是工具输出字符或回放估算，不能写成已测 provider Token。随后 V2 从该 V1 提交继续。这个提交不等于 Live 门禁通过；main 与 release 标签暂不移动，仍不推送。

本轮 V2 的可选策略也按该授权记录为离线检查点：集成长日志输入字节−20.90%，普通任务0%，辅助记忆回放−54.02%。冻结 v2，v3 从其 fast-forward 后继续本地实验。所有百分比明确量纲和工作负载；未经真实模型配对测试不移动 main 或 release 标签。

初始化命令和提交 SHA 写入 `PROGRESS.md`。在当前 baseline 测试记录好后，脚本会配置本地身份、提交一次初始化快照、打 `baseline-v0`，并创建 `v1`–`v3` 分支。
