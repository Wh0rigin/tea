# Git 与 PR 流程

## 当前规则（2026-10-11）

用户已明确要求：**之后所有改动都使用 PR**。该规则替代早期本地分支实验中直接 fast-forward `main` 的操作约定。

1. 阅读仓库 `AGENTS.md` 和 [贡献指南](../CONTRIBUTING.zh-CN.md)，保留无关的本地修改。
2. 更新远端引用，复用适合的已有 PR 分支，或从远端 `main` 创建 `fix/`、`feat/`、`docs/` 主题分支。
3. 完成改动、实际请求的检查和结果记录。提交消息里的百分比必须写明量纲、对照与工作负载。
4. 提交并推送主题分支，创建或更新指向 `main` 的 PR。不得直接推送 `main`。
5. PR 写清修改、验证、实验来源、失败和限制；创建后将 PR 附加到当前 Codex 任务。
6. 未经用户明确授权，不合并 PR、不启用自动合并、不发布 release、不改写已发布历史。合并方式由维护者决定。

本轮用户要求测试并完善贡献流程，已授权准备和提交这轮 PR。后续按上述流程交付仓库改动，不再沿用早期“只做本地提交”的约定。

## 实验与发布证据

性能 PR 必须区分真实服务商 Token、估算、字符、字节和脚本用量。保存任务、模型/思考配置、初始快照、验收、全部失败和预算信息。

直接父版本配对 Live 数据和完整回归要求仍用于正式优化发布门禁；Pi 对比不是直接父版本的优化验收。基础设施、终端功能、文档和诚实标注的离线实验可通过 PR 审阅，不得因此声称正式门禁已经通过。版本冻结、release 标签与发布需维护者另行决定。

## 历史说明

`baseline-v0` 保存初始化快照。此前 V1/V2 经用户授权提交了离线检查点：V1 工具输出字符减少 23.41%；V2 人工长日志集成输入字节减少 20.90%，普通任务 0%，辅助记忆轨迹减少 54.02%。这些数值不是服务商 Token，也不是模型成功率。

Git 身份仅在本项目配置，不修改全局身份。历史提交和运行记录见 [项目进度](../PROGRESS.md)。
