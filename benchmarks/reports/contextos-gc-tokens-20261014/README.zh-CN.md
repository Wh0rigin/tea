# TEA 自动压缩与 GC：真实 Token 测试

[English](README.md)

## 结论

正常任务的 Token 优化门槛**未通过**。两版各 30/30 验收通过，但新版累计用量 **增加 6.54%**：1,381,824 → 1,472,253 Token。

- 小型项目（9 对）：减少 **9.87%**。
- 中型项目（9 对）：减少 **11.66%**。
- 大型项目（9 对）：增加 **38.87%**。
- 长会话，30 次读取后修复（3 对）：减少 **0.62%**。

这 60 次正常任务没有触发压缩，不能把下降归因于 GC。大型缓存键任务连续三次回退；大型 Unicode 首次新版走了 17 次请求、20 次工具调用，旧版为 6 次请求、6 次工具调用。存在执行路径波动与其他代码变化的混杂因素，目前尚未确定回退的因果来源。

## 真正触发压缩的专项

在同一新版代码内进行开关消融，两种真实工具输出构成的预置历史各重复 3 次，共 12 次，全部验收通过。历史构造不是模型生成，也不计为付费调用；修复和摘要均为真实 API 调用。

- 必须保留、达到阈值的历史：218,724 → 118,517 Token，减少 **45.81%**，已包含 3 次摘要消耗的 **13,595 Token**。开启组每次都完成一次压缩及 GC。
- 可由 ContextOS 淘汰、未达到阈值的历史：70,791 → 74,399 Token，增加 **5.10%**，两组都没有摘要调用；此差值不能归因于 GC。

实际回收示例：驻留序列化历史从 61,737 → 21,205 字节。这不是堆内存、磁盘释放量或 Token。没有删除已提交的历史文件。专项证明的是自动压缩与 GC 组合的效果，无法单独量化 GC 的 Token 贡献。

## 实验约束

固定 GLM-5.3-flash、enabled thinking、low、输出上限 4096，相同端点与初始仓库，包含缓存读写输入、思考输出和摘要。只测 TEA，没有重新调用 Pi 或 Claude。72 次全部通过，用量完整，无重试、无失败样本剔除；旧的未知用量预留独立保留。

正常任务比较 bdc06bc 与 381a937，两版均开启 ContextOS，旧版压缩/GC 关闭，新版开启；预算上限 USD 12、每例 1.4、每例最多 100 次请求、每轮 300 秒。专项预算上限 USD 8、每例 0.6、24 次请求，触发阈值为 80%，请求字节保护上限 80,000，最近历史 24,000 字节。保守计费估算分别为 USD 2.3431796 和 0.3989828，非账单。
