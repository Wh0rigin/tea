# V2 — Selective Memory and Tool-Output Management

## 2026-10-11 offline experiment checkpoint

Parent: V1 `c2a218d4daada6901038d30d149ee515d44910e7`. The user authorized recording acceptable offline improvements in a commit and continuing the next experiment. This report records serialized input reduction, not provider Token savings. Live gate remains INELIGIBLE.

### Hypothesis and implementation

Older discovery results and successful command logs are repeatedly serialized into later requests. Replace only sufficiently long, rediscoverable old tool results with an explicit record containing the original tool-call ID, complete output SHA-256, size and recovery instruction. Keep at least the latest two tool-result rounds. Include recovery guidance overhead in the final request comparison; send unchanged V1 input if bytes, characters or heuristic estimate do not decrease.

The authoritative history remains complete in memory. All source reads and evidence references, patch receipts, failures, zero-test outputs, user instructions and assistant blocks (including thinking/signatures/tool inputs) remain unchanged. Duplicate IDs, orphaned results, malformed pairings and non-allowlisted shell output are preserved. Default `historyStrategy=full`; `compact-tools` is an explicit experimental ablation.

### Integrated runtime measurement: primary offline result

All four runs execute the same 12 self-authored JavaScript fixtures with supplied patches, actual public tests and separate acceptance tests. Comparisons use the same manifest, source snapshot, initial repository commits and acceptance-test hashes. Source is unchanged throughout all runs.

- Ordinary trajectories: `v2-smoke-full-20261011` / `v2-smoke-comp-20261011`. Both 12/12 accepted, 60 adapter calls and 12 validations each. Candidate's original and prepared request inputs are both **279,315 UTF8 bytes: 0.00% improvement, no compaction**. Independent full-arm total is 279,312; the three-byte difference comes from command timing text and is not a strategy gain or regression.
- Artificial long-log trajectories: `v2-stress-full-20261011` / `v2-stress-comp-20261011`. Both 12/12 accepted, 156 adapter calls and 108 validations each. Each fixture adds eight repeated real verbose diagnostic tests, rather than a model choosing to repeat them.
- Within the compact run, identical captured outputs produce **1,694,687 → 1,340,431 cumulative serialized adapter-input UTF8 bytes (20.90% reduction)**, including the added system guidance. Median per-fixture reduction **20.97%**, range **20.42–21.26%**. Cross-run full-arm total 1,694,647 → 1,340,431 also gives 20.90%; it includes small test-duration variation.
- Tool output is not shortened by this experiment: stress arms return 176,570 / 176,577 characters. The gain comes from the view sent to later adapter calls. There are 252 compacted-result occurrences, counted repeatedly across requests, not 252 unique tool executions.

### Auxiliary memory replay and negative controls

`v2-memory-replay-final-keep2`: seven trajectories, 79 paired requests using identical captured real WorkspaceTools outputs. Messages JSON: 3,630,112 → 1,578,605 bytes (56.51%). Helper complete() arguments: 3,797,829 → 1,746,322 bytes (54.02%). The helper uses a shorter fixed system prompt and excludes integrated recovery guidance; this is a separate metric from the 20.90% runtime result.

`v2-memory-replay-final-keep4`: retaining four rounds reduces helper complete() input by 37.09%. Short read, short validation and ordinary quiet successful-log trajectories have 0% change. All preservation checks pass, including four failure results and the evidence-refresh trajectory's two source generations plus 12 references. No provider request is made.

### Validation and interpretation

- `npm test`: **94/94 passed**. Includes memory pairing, immutable history, source refresh, malformed histories, config, integrated request fallback, real long logs and independent acceptance.
- CLI help and memory report commands work; `git diff --check` passes.
- Provider actual input/output/total tokens, model task success and billed USD: **NOT_MEASURED**. Scripted acceptance is not model success. Heuristic Token estimates are diagnostics only.
- Context diagnostics measure JSON `system/messages/tools` prepared for `adapter.complete()`, excluding the HTTP envelope/model/thinking fields. A provider preflight refusal would still count a prepared request; these fields are not actual network bytes.
- Stress fixture repetition and helper discovery histories are constructed workloads. Neither percentage predicts production traffic, provider tokenization, reasoning output, extra recovery calls or model quality. No latency gain is established; the concurrent runs are not a controlled latency experiment.
- Default remains full history. Selective memory is retained as an opt-in offline checkpoint; no main movement or release tag follows from these results.
