# ContextOS GC：功能与冷历史压力检查

[English](README.md)

## 改动

默认自动摘要和检查点 GC。只有检查点持久化成功后才释放旧正文；ContextOS 冷证据保存在加密载荷，召回正文 LRU 默认 256 KiB，用户原文、有效项目规则、待验证修改和未知计费保留。默认 4 MiB 常驻序列化历史触发保护，单会话日志与载荷容量 512 MiB；这些不是进程堆的硬上限。

磁盘仅收集所有已提交历史都不引用的孤儿载荷：24 小时宽限，单次最多扫描 1,000 项，持有单写者锁。完整历史不自动销毁，源码失效仍要求重新读取。

## 验证

- 全套 298/298；GC 专项 17/17，包含独立进程恢复、检查点后中断、提交失败、过期源码/规则、缓存与容量、未知计费、重置和损坏载荷。
- 组合检查 18/18；旧组合中的摘要后历史搜索入口缺口已在本地检查中修复。四组均实际执行独立验证，待验证状态不由摘要认证。
- 冷历史压力：12/36/72 工具轮次，各重复三次，GC off/auto 共18次，每次一次固定脚本摘要；常驻历史序列化字节分别减少99.85% / 99.95% / 99.97%。正文仍在磁盘，用户要求仍保留。

**这是序列化活跃历史的体积，既不是实际堆/RSS 降幅，也不是供应商 Token 降幅。** 所有注入摘要为脚本结果，新增供应商调用为0；没有新模型性能或默认配置收益结论。冷检索入口增加工具定义开销，需要真实固定模型对照另行量化。

初期失败保留在本地：默认持久化要求重置传配置；历史策略单项夹具需固定关闭摘要；新组合核查需把已归档前缀与保留后缀合并核验原文。未删除或重判历史付费数据。

## 限制

有界的是冷正文缓存；日志元数据、原文要求与任务状态仍可增长。单会话容量不等于全机总容量；旧会话需显式归档/删除。极长日志仍增加启动、搜索和GC耗时。全量历史回退会重新占用内存。本地功能检查不能证明生产规模、跨模型泛化、长期故障率或Token无负收益。
