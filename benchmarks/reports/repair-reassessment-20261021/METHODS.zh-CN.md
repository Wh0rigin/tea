## 3. 模型、保护与预检

共同使用 GLM-5.3-flash、流式传输、thinking enabled / low；任务请求最大输出 131,072，派生 thinking budget 8,000。压缩请求沿用原有的独立输出上限 1,200，其 thinking budget 为 `min(8000, max_tokens − 1)`，即 1,199；本轮没有修改此策略。上下文配置 216,000，扣除任务输出预留和额外 4,096 后，输入保护为 80,832 个估计 Token，并不是允许 216K 的纯输入。

ContextOS 目标为 32,000 **字节**，启用自动压缩与 GC。每次最多 96 次工具调用、128 次传输请求，单请求 900 秒，Agent 墙钟 30 分钟。每次控制分配 10 USD，两个基准共分配 240 USD；控制费率和分配额度不是实际账单。

离线预检不调用供应商：每版本、每基准覆盖 10 个合成 SSE 响应、9 次真实工具操作；独立导出补丁校验、源码包和协议字节核验均通过。合成使用量、静态提示字节数不充当真实 Token 收益。

## 4. 计量与失败保留

每次请求通过原生账本与独立传输审计逐项核对请求数、请求哈希、供应商 usage 和模型控制参数。输入包含缓存读写且只计一次；输出中包含的思考 Token 不再重复相加。若供应商没有单独报告思考量，则该分项保持未知。

原生运行没有终态摘要时，共享采集器可以保存**已经写入**的账本并独立核对用量，不能凭此补造 Agent 完成状态或官方成绩。原始失败与预留仍保留。推理后发生的原生任务失败只允许继续执行预先规定的其他独立尝试；推理前的基础设施故障或未排空的转发请求会停止计划。

报告分别列出：

1. 官方整题通过和部分检查成绩；未评分单列，不按已评分分母掩盖失败。
2. 端到端通过：官方整题通过，且 Agent 状态为 `completed`；主分母是预定尝试数。
3. 所有尝试的实际消耗：包括失败，仅在用量全部可核实时给出总量及其变化。
4. 同等完成工作的 Token 效率：同题同次配对，初始源码、指令相同，两组均完成且官方满分，计量完整。失败或未配对样本不进入成功工作 Token 柱形图。

Token 变化为 `(候选 / 对照 − 1) × 100%`，负值表示减少。解题率变化使用**百分点**；不把解题率变化和 Token 变化混为同一种百分比。每题只有两次重复，模型没有可固定的供应商随机种子；单题波动、成功配对子集的选择效应及样本规模必须随结论披露。
