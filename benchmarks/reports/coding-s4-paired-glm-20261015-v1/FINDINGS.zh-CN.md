# S4 结果解释与人工核查

## 结论

本组 48 次测量累计 Token 增加 **48.39%**，双方通过的 18 对也增加 **54.57%**。候选未满足预设门槛，运行时实现已撤销；不发布生产节省声明。所有用量来自 provider，包含缓存输入，思考包含在输出中。

完整验收 20/24 → 21/24；独立代码测试 23/24 → 22/24。候选第三轮转账修改了受保护测试文件，导致该题从 3/3 降至 2/3。总验收增加不能代替逐题质量和代码行为检查。

## 为什么没有获得整体收益

S4 必须等完全相同的验证命令成功后，才能把旧失败转为引用。11 次触发任务中，19 条日志都只在最后一次模型请求中被引用，之后没有继续调用工具。该机制在本组只影响收尾请求，没有缩短此前的编写、测试和修复循环。

这些触发任务共消耗 615,943 Token，其中 546,920 在最后请求前发生，最后请求 69,023。最后请求的用量不等于节省量：本组没有对同一前缀执行第二次付费反事实请求。

请求次数 174 → 216，成功源码补丁 31 → 40，成功测试补丁 15 → 27。全组增量 283,407 Token 中，转账、CSV、依赖图、分页分别贡献 95,375 / 69,821 / 65,477 / 43,678。轨迹差异发生在日志替换生效前；这些独立模型运行的差异不足以证明替换日志导致修复次数增加。

每题仅三次，未证明统计显著性。本组均为新会话编码任务，没有验证跨任务长会话的累计收益。固定历史控制证明可减少序列化字节，不等于证明整组 provider Token 下降。

## 候选失败样本

### CSV：遗漏合法的混合字段

`l2-csv-r3-candidate`：自身测试通过、隐藏测试失败，52,012 Token。

人工离线复现 `parseCsv('a,"b"')`：预期 `[['a','b']]`，实际抛出 `SyntaxError: quote inside unquoted field`。生成实现的逗号分支遇到后续引号时跳过结算字段，导致前一字段残留。这是实现缺陷；原失败结果保持不变。

### 并发调度：空输入不结束

`l3-scheduler-r3-candidate`：10 分钟后取消，25,141 Token 用量完整；公开和新增测试未通过，隐藏测试通过，保护文件未改。

生成的 `mapLimit` 只在工作完成回调中检查完成数。空数组不启动 worker，也没有调用 resolve。离线以 100ms 计时器竞争验证 `mapLimit([], 2, x => x)`，仍处于 pending；原有公开测试已覆盖空数组。

模型重复运行挂起的命令，多次触发 120 秒超时，没有修复该边界。超时属于执行异常，S4 保留这类输出，未将其当作已解决的普通失败。该样本没有触发 S4。

### 转账：修改保护文件

`l4-transfers-r3-candidate`：原有、新增和隐藏测试均通过，但修改 `tests/public.test.mjs`，按冻结规则判定未验收，27,585 Token。该样本没有触发 S4。不得事后因其代码测试通过而放宽保护规则。
