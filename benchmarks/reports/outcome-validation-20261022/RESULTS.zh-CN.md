# 需求结果验证与入口崩溃复验：实现及离线诊断

日期：2026-10-22。基线为 `b2f202c0f9b75758428222579124621a28d492ca`；候选各源码 SHA-256 见 [verification.json](verification.json)。

## 本次修改

- 在已有工作响应中维护简短的“需求 → 可观察结果 → 检查”对应关系，覆盖默认值与交互行为；这是模型指导，不是独立规划调用或自动验收器。
- 要求验证实际输出与持久化结果；后台任务须检查启动调用返回后的持续工作，并清理测试工作进程。引擎没有硬编码具体项目、线程禁令或参考答案。
- 将直接 Python 模块/脚本、Node 脚本的明确未处理异常纳入原有待验证状态。普通命令退出非零不等同于产品崩溃。
- 原命令成功复验才能清除入口崩溃义务。源码修改、不同参数的入口或不相关测试通过均不能代替。复用已有最多两次结束提醒，随后返回 `needs_validation`，不无限重试。
- `run_shell.expected_exit_code` 可事先声明故意触发异常的负向探测；仅在实际退出码匹配时排除新崩溃义务，不能事后重命名已有失败。该字段用于异常分类，不是通用验收证明；不改变命令执行、审批或权限。
- 复用现有状态持久化、压缩和 GC 路径；handoff 另外携带未解决命令和不可用检查。
- 提示在命令用法错误时修改调用，复用有效证据、调整无新增证据的搜索策略。没有新增检索批处理器，也没有自动判定某次读取无用。

## 相同操作的旧版与候选版对照

公开诊断脚本：[check-entry-closure.mjs](../../../scripts/check-entry-closure.mjs)。模型选择均由脚本给定，命令与测试实际执行，无 API 调用。两版使用相同脚本、任务和初始文件。

1. **真实入口崩溃，再通过不相关单测**：旧版 `completed / validationPassed=true`；候选 `needs_validation / false`，保留原入口命令。
2. **修复代码，但只跑不相关单测**：旧版仍判完成；候选仍要求原入口复验。
3. **修复并重跑原入口**：两版均完成，模型请求均为脚本化 3 次。
4. **正常成功**：两版均完成，请求均为 2 次。
5. **处理过的参数错误，再跑通过的单测**：两版均完成，请求均为 2 次。
6. **预先声明的异常负向探测**：两版均完成，请求均为 2 次。
7. **已观察崩溃后改称预期异常**：旧版完成；候选保留义务。

候选在第 1 项多出 2 次既有提醒请求，在第 2、7 项同样多出 2 次。脚本刻意不响应修复提醒，所以此处证明的是阻止错误收尾，不能说候选自主解决了任务。逐项状态见 [baseline.json](baseline.json)、[candidate.json](candidate.json)。

## 真实进程生命周期反例

新增 Python 专项实际执行两种启动程序：守护线程与独立子进程。两者均退出 0、写入 `running=true`，但仅独立子进程在启动调用结束后生成处理结果。测试没有读取 DeepSWE 隐藏判定器或参考源码。

这证明原先的状态/退出码断言不足；它不是“模型现在一定会选择正确结构”的证据。引擎不会自动构建任意项目的后台行为测试。

## 行为差距与代价

已对齐一部分：不能通过无关绿灯掩盖已观察的入口异常，失败状态不会因压缩或恢复遗失。

仍未证明对齐：模型是否完整提取需求、选对后台架构、编写足够强的后置条件测试，以及 Helm 的检索收敛与长任务效率。需求清单和结果验证目前主要依靠提示词指导，不能等同于强制完成全部需求。直接 Python/Node 入口的识别是保守子集；Shell 包装器、其他语言、自定义可执行程序以及被截断后缺少异常标记的输出仍可能漏检。明确异常也可能来自依赖或环境，待复验不等于已判定根因是源码。

代价：默认七工具下，系统提示从 1,047 增为 1,722 UTF-8 字节，工具定义从 3,380 增为 3,571 字节，合计增加 **866 字节（19.56%）**。这是静态局部载荷，不是整个请求涨幅，也不是 provider Token 涨幅。正常成功样本没有增加脚本化模型回合，但每轮新增指导仍有输入成本；失败样本会增加有限的纠正回合。

**本次没有重新运行 DeepSWE、WorkBuddy 或 Pi，也没有新的真实 Token 数据。不能将旧成绩改成新成绩，不能据此宣称已达到 Pi 的 4/4 或产生 Token 收益。** 后续需要冻结候选版本、相同配置做真实对照，并增加未见任务，才能判断行为指导是否提升自主解题能力以及额外验证是否值得。
