# V1 — 真实工具输出与可执行链路检查

日期：2026-10-11。候选仍未提交，`main` / `baseline-v0` 未变。以下实验均没有付费模型请求，不能通过 Live Token 门禁。

用户随后明确批准按这些离线结果提交并进入 V2。V1 提交采用最终工具字符 −23.41%、长日志 −86.47% / −54.06% 的准确口径；本报告的历史“未提交”决定由该后续授权更新，Live 门禁状态不变。

## 长日志输出

针对两个固定自编 Node 测试程序，动态加载 `baseline-v0` 的原工具，与候选工具运行相同命令。原始日志约 165k 字符，分别成功和失败。

- 原工具两项均因输出量超过阈值提前杀死进程，返回 `exit=SIGTERM`，丢失尾部标记及测试总结。
- 候选成功命令完整结束 `exit=0`，返回 1,899 字符；相对原返回 14,035 字符减少 86.47%。
- 候选失败命令完整结束 `exit=1`，返回 6,448 字符；减少 54.06%，保留失败断言和总结。
- 候选实际耗时约 1.66–1.69 秒，原约 0.37 秒；原版提前结束，因此不能声称延迟改善。
- 策略：stdout/stderr 分别保存有界头尾及完整流哈希；成功每流限 2,000 字符，失败每流限 6,500 字符；最终返回不超过工具总上限。Windows 超时结束进程树。输出体积不再导致中止。

原始本地诊断：`benchmarks/results/command-output-wKAWEz/report.json`。此比较确实执行了子进程，但没有测模型输入、输出或账单 Token。

## 可执行 fixture 链路

`runtime-smoke.json` 包含 12 个自编 JavaScript 小仓库，覆盖过期/刷新、重试预算、路径、分页、缓存、排序、Unicode、配置解析、搜索、迁移和异步队列。仓库通过固定日期/文件内容生成可重复 Git commit。初始公开测试必须通过，独立验收必须完成且失败。

- 同一候选引擎的 `baseline` 与 `v1` 上下文策略，分别执行相同脚本化工具动作、给定修正和真实测试。
- 两侧独立验收均 12/12，通过相同 manifest、源码快照及初始仓库 commit 校验；运行期间源码保持不变。
- 返回工具字符 15,552 → 11,910（−23.42%）。这只表示脚本化工具结果体积，不能说明实际模型 Token 或模型正确率。
- `baseline` 是原清单/读取策略的消融配置，使用修复后的候选引擎；不是历史 `baseline-v0` 源码执行。
- 负例：不修正源码时，模型脚本虽然返回 completed、公开测试虽然通过，独立验收仍拒绝；提前 `process.exit(0)` 不能跳过隐藏断言；验收异常保留任务账本、费用 checkpoint 和最终失败摘要。

成对运行：`runtime-final-baseline-20261011`、`runtime-final-v1-20261011`，位于忽略提交的 `benchmarks/results/`。这两次运行完成于后续超长读取去重安全补丁之前；快照哈希准确记录当时实现。

最终安全补丁后复测：`runtime-verified-baseline-20261011` / `runtime-verified-v1-20261011`，两侧仍各 12/12，工具字符 15,551 → 11,911（约 −23.4%）；同 manifest/source/仓库 commit，源码前后哈希一致。测试输出中耗时文本造成少量字符波动，因此不对字符差进行 Token 统计推断。`npm test` 71/71 passed，包含早退、超时、验收异常与截断范围负例。

## 后续正确性修复

真实 Runtime 检查发现并修复任务哈希启动错误、Git/help/零通过测试被当成验证、修改后验证状态失效，以及超长首读只展示前缀却将完整范围引用为已发送的错误。现在只有完整展示的源码范围才允许证据去重；截断请求需缩小行范围。账本归一化包含缓存输入，未知用量为 `null`，脚本化结果不发布 provider 实测总量。SSE 按连续 UTF-8 解码并处理无末尾换行的结束事件。
