# PR24 DeepSWE 测试结果

## 结论：未达到采用标准

本轮整题验收 **2/4（50%）**，上一轮 PR22 为 **3/4（75%）**，观察通过率下降 **25 个百分点**。累计 **4,220,300 Token**，比上一轮 4,824,790 少 **12.53%**。正确率下降，不能把这个数字称为有效优化。

这次未同期重跑父版本或 Pi，因此以上是历史重复样本比较，不能证明提示段落导致了下降。题目仅为两道已见任务、各重复两次，不是完整 DeepSWE 得分。

## 四次尝试全部保留

- Helm 第一次：官方 **7/7，通过**；1,567,257 Token，80 请求。本地状态为 `needs_validation`。
- Mnamer 第一次：官方 **370/370，通过**；524,799 Token，29 请求；本地完成。
- Mnamer 第二次：官方 **368/370，失败**；863,047 Token，38 请求；本地完成。新测试 49/51，旧测试 319/319。
- Helm 第二次：官方 **1/7，失败**；1,265,197 Token，51 请求；本地输入上下文保护停止。新测试 0/5，旧测试 1/2。

所有用量完整，共 198 个已提交请求；无网络重试、无未知用量。输入 2,713,062、输出 109,734、缓存读取 1,397,504、缓存创建 0；思考输出只计入一次。失败样本也包含在总量中。

按任务历史总量比较，Helm 增加 **28.82%**，Mnamer 减少 **47.15%**；整体下降不能掩盖任务级差异和未完成情况。

## 失败与行为分析

**Mnamer 第二次：提示未稳定落实。** 官方失败为“批量上限 0 不处理文件”与“嵌套状态路径日志”。模型生成的状态/日志写入函数未创建父目录，与后一失败相符；通过的第一次实现有对应处理。仅凭失败名称不能确定前一项根因，扫描循环本身已有零预算判断，尚需另行检查参数解析等路径。没有读取隐藏判定器源码，也没有把两次实现差异视为单变量因果证明。

**Helm 第二次：检索较多且压缩后恢复不足。** 重复的同参数读文件/检索/召回共 22 次，第 82 个工具操作才首次修改。两次压缩都正常结束，摘要分别输出 1,274、1,512 Token；随后估算输入 83,984 超过可用 80,832，触发 `MODEL_CONTEXT_LIMIT`。窗口仍是 216,000，但原配置预留 131,072 输出等空间。这不是官网流中断，也不是旧的 1,200 Token 摘要截断。被阻止的请求没有提交，停止前没有执行验证命令，补丁未完成。

**Helm 第一次：官方通过不代表本地全验证通过。** `go test ./pkg/action/` 中一个测试期望 HTTP 404，容器网络不可达导致断言失败；重跑仍失败，TEA 保留 `needs_validation`，未虚报验证完成。其命令包普通测试与先前超时的构建已复测通过。全轮“官方通过且本地完成”为 1/4，官方整题通过仍单独报告为 2/4。
