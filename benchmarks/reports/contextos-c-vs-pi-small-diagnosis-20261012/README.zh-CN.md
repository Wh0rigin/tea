# 小任务 Token 诊断：TEA ContextOS C / Pi

[English](README.md)

## 结论

主要成本来自额外请求和验证受阻后的反复操作。9 个小任务中，TEA 单次请求平均更小，任务总请求更多。优先改工具能力说明、不可重试错误反馈、补充验证通道和停机条件；现有记录没有显示小任务发生可恢复历史压缩。

这是对已结束实验的观察性诊断，没有新的模型请求、计费或 Agent 运行时变更。来源为默认 24 次工具额度实验的全部 9 组小任务：12 文件，三类自编 JavaScript 缺陷，每类三重复，同 GLM-5.3-flash、enabled/low、4,096 输出上限。原实验和失败不重写。

## 1. Token 怎么多出来的

- 总量：TEA **155,754** / Pi **102,293**，多 **53,461（52.26%）**；完整验收双方 **8/9**，独立代码/范围检查双方 **9/9**。
- 请求数：**79 / 46**，TEA 多 **71.74%**；平均每请求 **1,971.57 / 2,223.76** Token，TEA 小 **11.34%**。这是总量的算术分解，不能解释成同一轮提示的因果对照。
- 缓存键任务三次合计 **21,653 / 33,105**，TEA 少 **34.59%**；重试任务 **46,101 / 33,749**，多 **36.60%**；Unicode **88,000 / 35,439**，多 **148.31%**。
- 最坏 Unicode r3 为 **59,459 / 11,007**，净多 **48,452**，占全部净超额 **90.63%**。仅作敏感性核查：去掉这整个配对后，剩 8 组仍为 **96,295 / 91,286**，TEA 多 **5.49%**。该核查不替代全体结果，也不是已实现收益。

## 2. 工具权限与说明不匹配：最高优先级

9 个 TEA 加密会话中共 **21 次 run_shell 拒绝**，其中 **20 次发生在公开测试已通过的状态下**。19 次为“Shell operators and multiline commands are blocked”，2 次为“Unlisted shell commands require an interactive terminal for approval”。

模型想执行 `node -e "..."` 等边界检查。当前字符串规则扫描整个命令中的 `; & | < >` 等字符，连引用参数内 JavaScript 的分号、箭头函数 `=>` 也会触发拒绝。改写引用或更换 `-e/--eval` 往往仍不可用。无交互终端时还无法取得批准，但工具一直暴露，错误也没有不可重试类别、建议动作或累计失败信息。

Pi 在这次原生实验使用 `--no-approve`，TEA 保留验证白名单和非交互审批限制。额外调用与这个能力差异直接相关；此次对比不能隔离为“记忆机制导致多用 Token”。Pi 没保存完整命令原文，不能逐条认定它的额外边界检查覆盖。

**办法：**会话开始时固定公布实际能力和平台；错误返回通用类别、`retryable=false`、允许的替代动作。以“能力类别＋工作区版本＋批准状态”识别重复拒绝，避免换几个字符又重试。为需要补充验证的任务设计 `program/args/stdin` 形式的结构化执行通道，使用直接进程参数避免 Shell 引用问题；继续遵守命令批准与文件权限。结构化参数解决引用问题，不提供操作系统隔离。优先支持可移植的测试入口，不能为这三个样本写特例。

底层进程启动已经使用 `shell:false`（Windows npm 是单独兼容路径）；需要改进的是上层单个命令字符串的过滤、参数解析和能力协商。直接删除字符过滤或开放任意脚本，不属于这份方案。

## 3. 最坏案例：拒绝之后退回修改代码

Unicode r3 的实际序列：

1. 请求 1–6：读规则、源码、公开测试；首次补丁有逻辑问题，读回后再次修复；公开测试通过。这个读回是有效纠错。
2. 请求 7–12：连续六次补充验证被拒，包括 Windows 环境中的 `/dev/stdin` heredoc。代码没有变化，公开验证状态持续有效。
3. 请求 13：改成 `function __unused__`，丢失原有导出；请求 14 补丁搜索失败。
4. 请求 15–18：尝试 `type` 被拒、绝对路径读取被拒、重新列文件；随后写出 `function export` 这样的无效声明。
5. 请求 19–22：再次补丁搜索失败、搜索代码，恢复 `export function truncateText`，再次运行公开测试。
6. 请求 23：再次请求不可用 Shell；请求 24 又申请工具，触发 25 次尝试、24 次实际执行的额度上限。最终代码通过独立验收，但流程未正常结束。

首个公开测试完成后的请求 7–24 共 **49,778 Token**。这包含后续修复、再次验证和回答机会，不能全部当作可删除浪费。两次 API/语法回退是工具变更中的直接事实；“拒绝导致模型心理上混乱”只是解释性假设。

![Worst-run cumulative measured tokens](small-unicode-r3-timeline.png)

**办法：**把“能力不可用”与“测试失败”明确分开；前者不能成为改源码的理由。完成状态应依据用户要求、实际源码版本、目标边界验证和原生流程共同判断。只有仍有需求或新的问题证据时才继续修改；重复不可执行尝试应转为明确的验证限制或未完成状态。不能仅因一条公开测试变绿就报告成功。

## 4. 测试覆盖不足，模型有合理的额外验证需求

Unicode 公开测试只覆盖 `hello/hi` 等 ASCII 和零上限，没覆盖代理对；重试公开测试不覆盖零预算和最终错误传播。初始缺陷代码本来就能通过公开测试。模型补充检查方向是合理的，执行路径受阻才是成本放大的关键条件。

**办法：**区分回归测试和任务目标验证，给需求记录可观察的验证证据；提供已有相关测试的发现与执行入口，支持经批准的临时验证而不修改用户要求保留的测试。完善公开测试属于新的实验配置，必须双方使用相同的新快照、另报结果；不能把更强的测试替换进旧实验再重新计算收益。用户目标尚未验证时，应明确未完成或未验证。

## 5. 补丁与路径反馈让恢复多走几轮

最坏案例有 **5 次成功补丁、2 次搜索文本未找到、1 次绝对路径拒绝**。成功补丁仅返回 `Updated <path>`，没有新版本或改动片段；工具说明也没明确写必须使用相对路径。运行时会正确屏蔽旧源码，但模型缺少便宜、直接的当前版本反馈，容易在旧文本上再补。

**办法：**补丁返回路径、前后源码哈希、改动范围和小段当前内容；搜索失败时明确需读取该文件的新版本。路径要求写入工具说明，在工作区内部安全规范化绝对路径，工作区外继续拒绝。无变化补丁不重置验证可作为防御性改进，**本例没有无变化成功补丁**，不能将它算作本轮原因或收益。

## 6. 压缩、缓存与思考参数的实际影响

- 全部小任务最大完整请求 **18,172 字节**，低于 ContextOS 的 **32,000 字节**软目标；**可恢复内容驱逐为 0**，工作目标额外重锚定也为 0。发生的是旧源码失效屏蔽，累计请求字节 **687,936 → 673,455（−2.10%）**，这是字节，不是新测 Token 收益。没有丢掉可恢复历史的直接证据；失效提示是否影响后续行为仍需单因素实验。
- TEA 的输入占 **96.25%**；输出总量 **5,848**，包含思考。大量成本来自每次请求重带已有内容。降低输出上限或思考等级不是优先措施，可能改变正确率及比较条件。
- 小任务缓存输入占比 TEA/Pi **82.70%/67.85%**。TEA 的命中比例已更高，缓存读取仍计入 Token；高命中不能抵消额外请求数。固定输入/缓存读/输出 USD 0.80/0.23/2.80 每百万的敏感性估计为 **0.065637/0.048237**，只是算式，不是实际账单。

**办法：**先减少反复请求，再研究稳定前缀和阶段合并。避免短会话另付费生成摘要。Anthropic 的缓存文档要求前缀一致，可作为结构设计参考，但不能据此断言 GLM 中转端实现相同。[官方缓存文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。

## 7. 工具额度、统计与泛化

24 次额度允许最坏例继续尝试，直至触顶。单纯提高额度会增加可支付的失败链长度；降低额度又可能截断必要修复。额度是资源上限，需配合进度检测，不能充当完成逻辑。

每类仅三次重复，一个配对贡献 90.63% 净超额，表明均值对长尾敏感。公开完整验收还存在原生测试命令识别假阴性；小型 Pi r3 代码正确但测试未确认。应分别报告代码正确率、任务要求完成、请求数、失败类别、全体总量和配对分布。

## 改进顺序与验证门槛

1. **先做能力说明与错误分类单项**：保留原权限；重复拒绝按能力原因去重并给可执行替代路径。
2. **再做结构化补充验证单项**：保持批准和范围规则，覆盖平台、带空格路径及多种测试框架。
3. **随后做进度与完成判断单项**：允许必要的额外验证，检测没有源码、证据或能力进展的重复尝试；阻断失败验证诱发无依据改源码的链条。
4. **最后做版本化补丁反馈**：短的当前证据与相对路径指引；独立测它是否减少重读/补丁失败。

每候选先与当前 TEA 直接父版本配对，再用 Pi 作外部参考；同模型、思考、输出、额度、任务、初始 Git 内容、验收和总预算，不把多个修复合并后猜各自贡献。原三类小任务增加重复，并加入未用于设计的不同语言和真实仓库任务；中大型和长会话同测，避免小任务收益换来长任务下降。预定优先门槛为完成质量不下降、全部失败与费用保留、用量完整、源冻结，再判 Token 是否改善。改善幅度现在**未测量**，不预告节省百分比。

## 证据

只读检查了全部 9 个本地加密 TEA 会话，验证日志链和加密内容完整性；79 个原生请求哈希与公共网关的原记录一致，日志前后不变。只导出脱敏行为、版本哈希、计数和阶段，不导出密钥、签名思考或完整消息。原生工具尝试 84 次，实际执行 83 次，差异是一次额度拒绝。
